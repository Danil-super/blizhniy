## Первый инкремент: границы и доказательства

F07 воспроизведён настоящим HTTP handler и AuthRateLimiter на синтетических counters: пять regression cases падали до изменения. После изменения проходят независимые recovery/session/phone запросы, включая оба режима CAPTCHA; распределённая нагрузка по-прежнему достигает aggregate cap. Добавлены настоящие PostgreSQL проверки нескольких limiter instances, concurrent IP/email отказов и aggregate caps. Локальный auth mode не менялся.

Ревью F07 отдельно проверило Telegram start: его session admission предшествует phone admission. Один IP всё ещё может расходовать до 300 session slots, в том числе на неуспешные операции; бесконечного списания после session-IP denial больше нет. Это не обещание нулевого расхода всех бюджетов на любую бизнес-ошибку. Новый сквозной HTTP regression проверяет, что поток одного IP не блокирует независимое подтверждение телефона.

F09 проверен на исходных runtime-модулях (ошибка воспроизведена) и исправленных с синтетическими dependency adapters. Повторы происходят только по новому обращению спустя 5/10/20/40/60 секунд, без фонового таймера; одновременно создаётся одна инициализация. Auth закрывает не прошедший preflight pool и создаёт новый. Успешный runtime переиспользуется. Ни операции пользователя, ни COMMIT, ни отправка платежа/письма не повторяются этим механизмом. Отсутствие decoder socket и создаваемого systemd каталога `/run/blizhniy-media` допускает повтор, неверные владельцы/права и неготовая конфигурация — нет. Обязательный старый fail-closed тест сохранён.

Независимое ревью дополнительно воспроизвело реальный pg timeout без code. Перед удалением текста ошибки нормализуются только четыре точных сообщения установленного драйвера. Явные SQL/TLS-коды и безопасный cause code имеют приоритет; message/cause не сохраняются. Новый тест использует настоящий pg с собственным loopback TCP server, который задерживает или обрывает handshake: проверяются код, задержка и новая попытка. До исправления эти проверки падали. Поведение неизвестного COMMIT не менялось.

Реальная остановка/восстановление БД и decoder на staging, алерты и reboot drill остаются эксплуатационной приёмкой; тесты с adapters не выдаются за неё. Production-БД, её права, реальные данные, SMTP/Telegram credentials и платежные режимы этим инкрементом не изменяются.
