# F13 — фотографии при параллельной загрузке

Основа `30dcce5`, только локально. Не менять guard/порог четырёх чтений, upload admission, права и данные production. Оригинальный аудит: пятый из пяти допустимых public GET получает503/MEDIA_BUSY; браузер не повторяет загрузку.

## Контракт

- Единый read admission для public/private/admin: максимум4 активные операции, не более64 ожидающих, не более24 ожидающих на trusted ingress IP. FIFO внутри клиента, round-robin между клиентами. IP находится только в короткоживущей очереди, не в журнале/URL/постоянном кеше.
- Ожидание не более1500ms. Переполнение/истечение —503/MEDIA_BUSY и Retry-After1, без SQL/FS по ресурсу. Отмена удаляет ожидающую работу без SQL/FS. Освобождение идемпотентное; активная операция сохраняет slot до фактического завершения, даже при abort.
- Состояние очереди общее между Next bundles в одном процессе, как нынешний глобальный счётчик. Не объявлять его распределённым между процессами/VPS. Private/admin проверяют origin/CSRF, cookie и limiter до admission; репозиторий проверяет действующую сессию/роль после ожидания; public-authority проверяется после admission и после FS. Ничего не переносить из старого разрешения через ожидание, не кэшировать private bytes.
- Для публичных same-origin photo GET на клиенте максимум2 повтора с задержками от1s/2s, небольшим jitter, тем же URL без query/cookie/метаданных. Native img error не содержит HTTP-статус: возможен повтор404, но без повышения прав и без бесконечной петли. Unmount/src-change прекращают повторы. Загрузки, private POST и любые записи автоматически не повторять.
- Существующие WebP, размер≤2MiB, SQL before/after FS, no-store, приватные каталоги и auth/CSRF/ingress gates сохраняются. Уменьшенные варианты/иной cache policy требуют отдельной модели хранения и проверки отзыва; их не добавлять без измерения.
