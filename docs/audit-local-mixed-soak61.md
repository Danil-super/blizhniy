## Профиль

98 публичных читателей по очереди открывают главную, объявления, работу,
вакансии, заказы и поиск «ремонт», с паузой5 секунд после завершения ответа.
Начала распределены по первым5 секундам; у читателя один незавершённый запрос.
Ещё два синтетических аккаунта раз в30 секунд читают профиль; один сохраняет
изменения, читает их обратно и проверяет отказ старой ревизии. Каждые20 изменений
он выходит, проверяет отказ старой сессии и входит заново, сохраняя результат.

Вход обычный HTTPS API. Синтетические аккаунты/email подготовлены владельцем
локальной БД; настоящие CAPTCHA/регистрация/доставка письма этим не проверяются.
TLS CA проверяется, HTTP deadline5s; максимум ответа2MiB публично/256KiB приватно.
Cookie/пароли и тела ответов не сохраняются в отчёте. Публичная проверка —200,
завершённый HTML с h1 без стандартной Next error-page; это не браузерный рендер.

При review runner найдены аварийные ветки: отмена только пауз, отсутствие
метрики приватной сетевой ошибки и фиктивные5000ms для публичной ошибки.
Для следующих запусков HTTP связывает общий AbortSignal с timeout и проверяет
отмену до отправки; только cleanup logout разрешён после отмены. Все ошибки
получают status0 и фактически измеренное время. Сырой PG/assertion error из
административного runner больше не печатается.2/2 actual-source transport-теста

в успешном прогоне таких ошибок и отмены не было. Эти ветви не выдаются за
исполненные исправленной версией: её отмена/ошибки проверены отдельными тестами.
