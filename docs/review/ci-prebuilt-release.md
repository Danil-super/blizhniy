# Выпуск готовой сборки через GitHub Actions

Подготовлено для review владельца 29.10.2026. База: `21535ff1c8b353e2b3bc29614f4e5fa65541d52e`. До одобрения этот pipeline не опубликован; действующий guard не изменён.

Владелец одобрил оба diff и выпуск после успешного CI 29.10.2026: «Одобряю diff и выпуск после CI». Точный floor patch применён после этого ответа; `check:floor` прошёл. Остальные описания подготовки ниже фиксируют состояние до согласования; результаты GitHub release проверяются отдельно.

## Причина

В запуске Actions `40746663280` четыре проверки прошли, а deploy был отменён оператором для предотвращения повторной тяжёлой сборки на VPS с 2 ГиБ RAM. Отменённый запуск остаётся отменённым в истории. Сайт отдельно установлен и отвечает на health/readiness; это не зелёный результат автоматического deployment.

## Конкретные изменения

- [Diff реализации и тестов](ci-prebuilt-release.patch), SHA256 `def16d79aac04e070b899b16b71afa015e2c06b676d3edc676222e1f9045d640`.
- [Предложенный diff guard и его тестов](ci-prebuilt-floor.patch), SHA256 `f48f52b9e44939967c5ffa4aa384f87fada53b405dcb506a43b4f23f19f45dfb`. Этот patch пока не применён в основном checkout.

Сборка выполняется на Ubuntu24.04/Node22.23.3 без production credentials. Пакет содержит standalone, статические файлы, отслеживаемые исходники и скрипты, зависимость отдельного mail worker. В пакет не входят env/ключи/локальные runtime-данные. До передачи проверяются commit, BUILD_ID, lockfile, inventory SHA256, ABI, настоящий запуск standalone, Sharp WebP и импорты PostgreSQL/mail worker.

Deploy зависит от всех прежних validate/security/codeql gates. На VPS сначала сверяется SHA256 всего архива, затем inventory и совместимость, только потом копируются прежние закрытые env и запускается managed runtime. На VPS отсутствуют npm install/build. Исходный режим скрипта сохранён для существующих операторских вызовов; автоматический pipeline выбирает готовую сборку явно.

Build, браузерные postchecks и SSH/finalization выполняются на разных runners. Jobs с npm ci не получают VPS SSH key. Прежние browser/SEO/readiness/security-header проверки сохранены. Подтверждение либо откат выполняет отдельный job; при потере Actions/SSH действует прежняя 30-минутная lease. Host watchdog дополнительно сопоставляет точный release этой попытки: сбой повторного запуска того же SHA не откатывает уже работающую версию.

Имена artifacts содержат номер попытки сборки; deploy получает имя и digest через outputs успешного validate. Повтор только упавших deploy jobs использует исходный успешный artifact. После истечения однодневного retention нужна повторная полная сборка; отсутствие artifact блокирует deploy.

## Шесть точных замен ожиданий

Предложенный guard разрешает только перечисленные пары строк в указанных файлах, по одному в diff. Любое другое удаление assertion, изменение строки, её повторение или перенос в другой файл остаётся запрещённым.

1. CI runner для build фиксируется на Ubuntu24.04; layout runner остаётся ubuntu-latest.
2. Условие допускается только у нового upload-artifact; обязательные quality steps остаются без условий. Отдельный тест проверяет точное условие upload.
3. Проверенный code root получает 0755 вместо 0700 для чтения непривилегированным веб-процессом. Закрытый env проверяется отдельно на 0600; в production дальнейшую группу и режим env контролирует прежний web-runtime guard.
4–5. Те же проверки успешного SSH confirmation и rollback исполняются из нового finalize job.
6. Remote staging передаётся между jobs через needs.deploy.outputs вместо steps.ship.outputs.

Численные quality/security thresholds, правила оплаты, права БД и SSH host pin не меняются.

## Доказательства

- 2093/2093 native tests; types и lint без ошибок, сохранено прежнее предупреждение unused targetType.
- Shell-проверки acknowledgement, rollback, потери связи, блокировки параллельного deploy и неудачного повторного запуска того же SHA; ZAP result handling и expiry runner прошли.
- Настоящие npm ci и production build в отдельном чистом checkout без production secrets. Упакованы и проверены 3924 файла; standalone health, генерация WebP и реальные импорты worker прошли. SMTP/платёжные запросы не выполнялись.
- Отключение проверки SHA256 отдельного файла в тестовой копии заставляет негативный regression упасть; исходный файл восстановлен.
- Actionlint1.7.12: структура YAML, выражения, inputs/outputs и зависимости jobs без ошибок. Бинарник проверен по checksum официального release. Shellcheck/Pyflakes этим запуском не выполнялись; shell paths отдельно исполнялись regression-тестами.
- Предложенный floor patch прошёл проверку относительно базы в изолированном checkout и 24/24 теста guard, включая запрет неточных замен; это не применение guard в основном проекте.

Обновлённый Actions pipeline ещё не выполнялся на GitHub. После одобрения: применить только указанный guard patch, повторить проверки, открыть PR, дождаться CI, выпустить в main и проверить полный автоматический deploy с postchecks/finalization. При ошибке новый release откатывается прежним механизмом. Текущий работающий сайт до этого не переключается.
