# Новые оплаченные периоды — локальная реализация

13.11.2026. Часть этапа2 аудита (F01/F06), без push/production/реального провайдера.

Владелец разрешил продлевать действующее размещение заранее. Новый срок
добавляется после оставшегося оплаченного времени; после истечения прежнего
срока начинается с фактической доступности нового. Возврат идёт с последней
покупки и отменяет только добавленный ею интервал. Прежний остаток сохраняется.

## Модель и исполнение

0056 добавляет неизменяемый `payment_renewals`: две исходные покупки, прежнее
окно, отдельный добавленный интервал и итоговое окно карточки. Клиент не
задаёт даты; SQL выводит их под блокировками владельца/источника/карточки.
Старые intents/receipts сохраняются. Незавершённая покупка/возврат блокируют
следующую покупку. Успешная исполненная покупка перестаёт быть вечной
блокировкой только для объявлений, вакансий и заказов. Правило однократной
покупки отклика и других типов не меняется.

Первоначальная публикация и продление используют существующие канонические
проверки полей, телефона, владельца, версии, тарифов, фото и справочников.
Локальная политика допускает уже оплаченные карточки; по умолчанию выключена.
Ключ покупки фиксируется до запроса в fragment URL. Потеря ответа/reload
оставляют только связанный readback; новая покупка автоматически не создаётся.
Исторический ответ оплаты содержит купленный этой покупкой интервал,
а не выдаёт первоначальную дату карточки за начало нового оплаченного срока.

Журнал исполнения продления записывается до изменения карточки в той же
транзакции: защита checkout видит исполненную покупку, включая восстановление
истёкшей карточки. Любая ошибка изменения откатывает и журнал, и receipt.
Возврат изменяет услугу только после прежних доказательств capture/refund;
повтор не меняет срок ещё раз. Более ранняя покупка не возвращается, пока
есть действующее последующее продление или незавершённая покупка.

Незавершённый отклик продолжает запрещать редактирование полей/фото/видимости,
но не блокирует точные финансовые переходы, подтверждённые журналом продления.
Восстановление вакансии/заказа ищет точный текущий receipt среди финансовой
истории и не ограничивается первыми тремя UUID.

## Интерфейс администратора

Журнал показывает доступность возврата по существующей security-definer
проверке без SELECT новой таблицы для operator/web. Устаревшее решение
отклоняется SQL до INSERT. Только этот известный отказ проходит как
`REFUND_NOT_LATEST`/409 для approve; сообщения SQL не выдаются.
COMMIT/транспорт/readback с неизвестным исходом сохраняют исходный action ID.
При определённом отказе очищается только тот же ID; ошибка очистки блокирует
новые решения до восстановления сохранённого действия.

## Границы допуска

13.11 владелец одобрил точный пакет guards/builders и установку только0056.
На постоянном локальном стенде установлен полный56; сквозная приёмка трёх
типов и перезапуск завершены. [Доказательства и ограничения](audit-placement-renewals-local-activation.md).
Он сохраняет старые54/55, допускает exact56 только по owned local-primary
пути и полному journal/fingerprint. Новых GRANT/ролей нет. Производственный
reconciler не получает допуска56; production остаётся отдельно от этого кода.
Откат0056 отказывается удалять непустую историю продлений.

`BLIZHNIY_PLACEMENT_RENEWALS=local-v1` не устанавливает схему, роли или права.
Без флага интерфейс/обычная политика остаются прежними. Неверная схема,
права или журнал закрывают запуск. Никаких настоящих операций ЮKassa нет.
