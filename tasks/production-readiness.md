Кандидат 0086 добавляет серверную часть регистрации Push. Браузер может иметь одну запись на действующую app-сессию. Регистрация требует сохранённого включения Push в профиле, штатной cookie и совпадения аккаунта. При выходе или успешном входе под другим аккаунтом отзыв прежней сессии удаляет её запись. После истечения срока сессии или подписки сервер отказывает в показе. Проверка показа сверяет запись с текущей cookie и сохранённой настройкой, не обновляет срок активности и использует отдельный лимит запросов. Браузерная часть должна заново запросить подтверждение подписки после входа в новую сессию. Для разрешённых адресов проверяются HTTPS, точный домен и маршрут провайдера, канонический ключ P-256 и длина секрета подписки. Web-роль имеет доступ только к трём функциям схемы Push. За флагом `BLIZHNIY_PUSH=inbox-v1` остаются API и публичный ключ приложения. Перед включением нужны проверенные очередь, сервисный воркер браузера, отправка и приёмка на тестовом получателе. Для Push кандидат 0087 ставит новое событие в очередь только для устройства текущего получателя и только при включённых канале и категории. Перед отправкой и показом эти условия проверяются повторно. Браузеру передаётся зашифрованный идентификатор доставки. Текст события загружается пользователем через обычный вход в кабинет. Отдельная роль воркера имеет три служебных вызова и получает только сведения, нужные для отправки конкретной задачи. Web Push 404 и 410 снимают конкретную подписку, 429 учитывает Retry-After, ответ 5xx или потеря ответа оставляют результат неопределённым без автоматической повторной отправки. Провайдер заменён управляемым транспортом, шифрование RFC 8291 выполняется библиотекой.
