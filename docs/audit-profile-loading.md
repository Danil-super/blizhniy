Продолжение: [организация и история платежей](audit-organization-payment-history.md)
также переведены на отдельные первичные экраны; ниже сохранён исходный замер

Локальный инкремент после9df81d7. Цель — убрать старый CabinetClient и SDK
из обычного первого открытия кабинета, сохранив действующие редакторы.
Два российских сервера, production, схема/права БД и платёжные режимы прежние.

## Граница загрузки

- DashboardShell использует лёгкий CabinetProfileBar. Первичные данные
  приходят из существующего CookieCabinetProfileProvider, а legacy-ветка
  загружается отдельно. Старый экспорт профиля остаётся адаптером к тому же View.
- View сохраняет прежнюю карточку, эффекты открытия по URL/retained avatar и
  ключ редактора по ownerKey. Дополнительно он скрывает данные, если identity
  не соответствует текущему userId, либо идентификация ещё не подтверждена.
- SettingsPanelLoader импортирует существующий редактор только при открытии.
  Во время загрузки и после ошибки доступны закрытие и безопасная повторная
  попытка. Закрытие вызывает прежний clearSettingsDraft: незавершённое фото
  не должно заново открывать окно. Позднее завершение импорта после unmount
  игнорируется; в state сохраняется тип редактора, а не старые props владельца.
- SettingsPanel и AvatarEditor не переписаны: тела функций побайтно совпали
  с9df81d7. SettingsPanel теперь экспортируется для загрузчика. Email, поля,
  валидация, сохранение, Telegram и обработка фото остались прежними.
- CabinetEntryClients выбирает существующие PostgreSQL-панели. Legacy-ветки,
  организация и история платежей импортируют старый модуль по необходимости.
  Чистый CabinetCapabilities выделен отдельно. Поведение CabinetDraftWorkspace
  не менялось: в новом режиме он по-прежнему владеет единственной drafts-панелью.
- Аватар48×48 использует next/image с unoptimized: приватный/data/blob источник
  запрашивается напрямую и не передаётся оптимизатору без cookie. Подавления
  линтера не добавлялись. Проверка общего Shell сменила только путь mock профиля;
  прежние assertions сохранены, guard/workflows не менялись.

  Новые проверки покрывают закрытие до импорта, отказ/retry, свежие props,
