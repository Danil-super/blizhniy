# F12 — ограниченный поиск PostgreSQL

Основа `774ee4f`. Только локально, без push/deploy/production и реальных платежей. Существующие тесты/guard не ослаблять.

## Контракт и первый план

- Сохранить trim/case-insensitive буквальную подстроку (включая `%`, `_`, обратную косую), q до200, выбранный город по точному публичному отображаемому имени. PostgreSQL18 lower с builtin pg_unicode_fast (полные Unicode mappings), затем LIKE с C-collation; проверить русский/латиницу/İ/греческую сигму против JS. Страница24, page1–1000. Не добавлять морфологию/fuzzy. Приоритет: объявления, вакансии, заказы, специалисты, ярмарка, категории, профессии; публикации published/created/id desc. Справочники — стабильный порядок sort_order/name/id для категорий и parent/name/id для профессий. Ошибочное статическое имя корня объявления заменяется текущим именем БД в тексте и matching поиска.
- Primary-route не вызывает legacy, demo и scanStoredResults. Оставить legacy-ветку отдельно для совместимости.
- Параметризованный SQL candidate-query UNION ALL по7 видам (5 физических источников) с q/city, общими public gates и стабильным ORDER/LIMIT25. MATERIALIZED CTE получают остаток общего окна25, остальные источники не исполняются после заполнения; обратное направление разворачивает также порядок источников. Затем не более3 пакетных readMany выбранных IDs существующими публичными stores (work/service по2 вида); восстановить порядок по(kind,id). Mapper-rejected записи пропускаются без query-specific ошибки; ограниченные окна читаются по keyset до25 действительных результатов. Новых write-grants нет.
- Переходы «Далее/Назад» используют cursor по последней/первой показанной публичной карточке (7видов, стабильные sortkeys, direction, hashquery/city), а не OFFSET с локальным исключением invalidIDs. Cursor не содержит скрытые/отклонённые ID. Это сохраняет границы страниц при недопустимых строках перед предыдущей страницей. Строгий URL-safe bounded DTO4096, значения только SQLparameters; cursor не авторизация. Старый числовой page безcursor читается через validated-prefix под тем же общим budget; произвольный глубокий jump может потребовать уточнить запрос, обычная глубокая навигация используетcursor.
- Все окна одного поиска ограничены deadline5000ms, не более25100 кандидатов и16MiB сериализованных DB rows. Нормальная cursor-страница читает25 кандидатов; missingquery не перелистывает каталог. Числовая совместимость не оправдывает повторный неограниченный обход. При resource-budget отказе не выдавать ложный пустой successful результат. Произвольно повреждённый каталог не считается исправленным этим инкрементом.
- Поиск только по тем полям, которые уже публичны в старом DTO. Для анкеты — текущее имя из профиля, текущая профессия FK и город; закрытые навыки/контакты не становятся поисковым каналом. У заказов публичный автор-константа сохраняет прежнюю семантику поиска. Категории ищутся по имени и активным прямым детям, профессии — по имени/родителю.
- Один REPEATABLE READ READ ONLY transaction с deadline5000ms, включая холодный shared initializer, pool/BEGIN/queries/COMMIT. Просроченный initializer не отменяется для auth и сохраняет search lease до фактического завершения. Driver query_timeout + server statement_timeout/transaction_timeout, без оставленного SQL после Promise.race. Отдельный узкий метод PostgresDatabase, обычные auth/payment транзакции не меняются. При ошибке read-connection уничтожается. Не более2 search leases на процесс; отказ при превышении. Просроченный checkout держит lease до фактического окончания pool acquisition, поздний client освобождается и не запускает SQL.
- Сначала baseline/EXPLAIN на собственной disposablePG18.6 с синтетическими данными. Индексы добавлять только при измеренном улучшении; не менять семантику ради индекса. Ограничить page и длительность даже при короткой/отсутствующей строке. Измерить missing/popular/deep и параллельные запросы; результаты не выдавать за productioncapacity или100active/30min drill.
