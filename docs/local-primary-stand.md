# Локальная проверка текущего PostgreSQL backend

Этот стенд не является старым Supabase-стендом `dev:local`. Он запускает текущую сборку сайта, cookie-авторизацию, настоящую отдельную PostgreSQL 18.6, частные фотографии и очередь писем. Рабочий сервер и его конфигурация не используются.

Используется проверенный Node.js 22. Сначала собрать приложение, не загружая
прежние `.env.local` и внешние ключи, затем запустить стенд:

```sh
env __NEXT_PROCESSED_ENV=true NEXT_TELEMETRY_DISABLED=1 npm run build
node --experimental-strip-types scripts/local-primary.mjs --prepare
node --experimental-strip-types scripts/local-primary.mjs --start
```

Для постоянной ручной проверки после завершения терминальной сессии вместо `--start` можно использовать `--background`. Launcher записывает собственный PID в приватный `launcher-process.json` и журнал в `launcher.log`; секреты в командную строку не передаются. Перед остановкой необходимо сверить PID, UID, cwd и точный аргумент `scripts/local-primary.mjs --start`, затем послать только этому процессу SIGTERM. Массовый `pkill` не используется.

Начальная страница: `https://127.0.0.1:3045/__local`. Сертификат самоподписанный и подходит только для локального адреса; браузер может попросить подтвердить локальный сертификат. Права доверия браузера launcher не меняет. На этой странице находятся логины двух синтетических аккаунтов и ссылки на сайт/админку/почтовый перехватчик. Для регистрации использовать только адреса `*.invalid`, например `new-user@local.invalid`.

`/__local/mail` показывает перехваченные письма подтверждения, восстановления и уведомления о блокировках. Ссылки переписаны только на локальный адрес. SMTP и внешний платёжный провайдер не вызываются. Локальная имитация оплаты явно обозначена; она не является проверкой реальной ЮKassa и не создаёт денежных операций.

## Изоляция

- Docker-контейнер создаётся с закреплённым digest PG18 и уникальной меткой проекта; PostgreSQL публикуется только на `127.0.0.1` со случайным портом. Повторный запуск сверяет полный ID, image, label и binding; чужой контейнер не усыновляется.
- Новая БД заполняется только справочниками из репозитория и двумя синтетическими аккаунтами. Production-данные и секреты не копируются. Миграции 0001–0032 применяются только к новой собственной БД. Существующий стенд автоматически не мигрируется; оператор Telegram проверяет журнал перед добавлением 0031/0032.
- Состояние, фотографии и случайные секреты сохраняются вне Git и рабочего стола в `~/.local/state/blizhniy/local-primary-private`, каталог `0700`, конфигурация `0600`. Ключи, cookie и пароли не печатаются в журналах. Удаление стенда не автоматизировано; остановка процесса не стирает тестовые данные.
- Next слушает `127.0.0.1:3046`, HTTPS ingress — `127.0.0.1:3045`. Публичный интерфейс не открывается. Ingress отвергает чужие Host/Origin/cross-site-запросы. Используются обычные защищённые HttpOnly cookies.
- Отдельный явно загружаемый `local-primary-preload.cjs` проверяет приватную конфигурацию и контейнер, после чего перенаправляет только ожидаемую `pg.Pool` на собственную loopback БД. Не подменяет SQL-ответы или идентичность: реальные runtime-права и проверки сессий остаются действительными. Next-процессу запрещены внешние fetch/socket обращения, включая SMTP и merchant.
- Production guards не ослабляются. Для локальных фотографий ingress использует те же production HTTP проверки/ownership и реальные репозитории с существующими локальными decoder/file worker. Это локальный контур, не утверждение о production sandbox.
- Локальная антибот-проверка выдаётся ingress только локальному браузеру; пароль, подтверждённая почта, роль и владение ресурсом всё равно проверяются сервером. Cloudflare не вызывается.

После изменения исходников остановить только этот процесс, заново собрать сайт и запустить стенд. Не запускать две сборки в один `.next` параллельно. `Ctrl+C` останавливает собственный Next и ingress, данные БД и файлы остаются для ручной проверки.

При перезапуске Docker может назначить новый случайный порт БД. Launcher сначала
проверяет прежний полный ID, image, метку проекта и единственный loopback binding,
затем запускает только тот же контейнер. Новый порт сохраняется в приватной
конфигурации только после повторной проверки живого binding, истории миграций и
ограниченной runtime-роли. Это не создаёт новую БД и не усыновляет чужой контейнер.

## Проверка объявлений

Войти обычным пользователем со страницы стенда → открыть «Мои объявления» →
создать объявление в исходной полной форме. Можно сохранить черновик или перейти
к оплате. Локальный симулятор предлагает ожидание, отмену и успешный платёж;
публикация происходит только после серверной проверки успешного результата.
Для проверки блокировки войти вторым демонстрационным аккаунтом администратора,
открыть `/admin/obyavleniya`, выбрать объявление и указать причину. Объявление
исчезнет из публичного каталога, причина останется в карточке владельца,
уведомлениях и `/__local/mail`.

Регрессионные команды (Node22):

```sh
node --experimental-strip-types scripts/check-local-primary.mjs
node --experimental-strip-types scripts/check-local-listing-blocks.mjs
node --experimental-strip-types scripts/check-local-postmoderation-payments.mjs
node --experimental-strip-types scripts/check-local-listing-ui.mjs
node --experimental-strip-types scripts/check-local-owner-actions.mjs
node --experimental-strip-types scripts/check-local-photo-ui.mjs
node --experimental-strip-types scripts/check-local-avatar-ui.mjs
node --experimental-strip-types scripts/check-local-admin-photos-ui.mjs
node --experimental-strip-types scripts/check-local-settings-ui.mjs
```

Последняя команда проходит реальный локальный интерфейс с cookie-авторизацией,
полной формой, фотографией, оплатой, публичной карточкой и блокировкой; оставляет
явно названное синтетическое объявление для просмотра. Это не реальная ЮKassa.
Карточки дополнительно проверяются browser helpers из
`tests/cabinet-card-browser-cases.mjs`: все статусы, клавиатура, 320–1440px,
axe и загрузка 20 приватных миниатюр не более чем тремя запросами одновременно.

Дальнейшая локальная версия включает [единые фото и действия владельца](listing-owner-actions-local.md).
Проверка от 21.10: [карточки админки и восстановление аватара](admin-cards-avatar-local.md).
Текущая локальная схема дополнена0027/0028; старые рабочие миграции не меняются.

Focused guard tests: `node --test tests/local-primary.test.mjs`. Это не замена browser/PG проверкам пользовательских сценариев.

Документация Next CLI: [next start](https://nextjs.org/docs/app/api-reference/cli/next#next-start-options). Context7 был вызван, но запрос завершился сетевым тайм-аутом; параметры сверены с официальной CLI-документацией и установленным Next15.

## Telegram Login

Подтверждение телефона подготовлено в текущем backend, по умолчанию выключено до настройки настоящего Login-клиента. Приватный локальный файл, Allowed URLs, команды миграции/включения/отключения и ограничения настоящей проверки описаны в [инструкции Telegram](telegram-phone-setup.md). Внешняя сеть остаётся закрытой; только явно настроенный режим разрешает официальные token/JWKS endpoints Telegram.
