# F15 — серверная нормализация аватаров

Основа `b67347f`, работа только локально. Существующий `parseProductionProfile` проверяет форму data URL, MIME, base64, размер и сигнатуру, но не декодирует пиксели. Проверка сигнатуры остаётся предварительным фильтром; запись нового изображения в primary требует изолированного декодера.

## Контракт

- Существующий origin/CSRF/cookie/limiter/owner/revision контракт сохраняется. До декодирования сервер проверяет действительную app-сессию, владельца и текущую revision. Во время native decode транзакция и блокировки БД не удерживаются. Перед сохранением повторно проверяются сессия, владелец и revision.
- Сервер получает только bounded canonical data URL JPEG/PNG/WebP (до 300 KiB). Используется существующий OS-ограниченный decoder, полное декодирование, запрет анимации, 24 MP input, до 2048 px output, WebP без исходных метаданных. В профиль попадает только проверенный output до 300 KiB; UI по-прежнему формирует квадрат 512×512.
- Decoder недоступен/занят/abort или некорректный reply: сохранения нет, без fallback на исходные байты. Повреждённый/неподдерживаемый input — 422. Не повторять запись и COMMIT автоматически.
- Нормализуется новый непустой аватар. Неизменённый сохранённый аватар не пережимается при каждом изменении телефона/настроек. Пустая строка удаляет аватар без запуска decoder. Старые данные не массово переписываются; прежние изображения нормализуются при замене, это не claim о ретроспективной очистке БД.
- Primary web и локальный manual ingress используют один и тот же store/normalization adapter; production — уже существующий защищённый socket, local — уже существующий systemd worker. Никакого sharp в веб-процессе, новых dependency/SQL schema/grants/guard или внешнего сервиса.
