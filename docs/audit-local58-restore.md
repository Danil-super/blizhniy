# Восстановление локальной схемы58 — 15.11.2026

Проверена свежая логическая копия постоянного синтетического стенда local58,
включая журнал связей фотографий, снимки исходных фото оплаты, terminal ledger
и учёт квоты. Production, российские серверы, банковский API и реальные
платежи не затрагивались.

## Процедура и исправление

Прежний helper57 закономерно отказывает схеме58. Новый сценарий сначала
воспроизвёл этот отказ на одноразовой PostgreSQL18: архив сохраняет данные,
но повторный parse шести CHECK с BETWEEN меняет constraint fingerprint.

Добавлены только отдельные не подключённые к runtime файлы58:
[helper](../scripts/restore-local-primary58-checks.mjs),
[SQL](../database/restore/local-primary58-checks.sql) и
[известный post-restore fingerprint](../database/refund-schema-local-primary-restored-0058.json).
Helper требует test runtime, postgres, полный исходный journal/SHA256 и точный
известный fingerprint до DDL. В одной транзакции пересоздаются шесть исходных
CHECK с валидацией строк; перед COMMIT сверяется прежний original fingerprint58.
Caller предварительно доказывает физическую принадлежность свежей одноразовой
offline цели. Одного имени БД недостаточно. CLI/runtime/deploy вызовов нет;
старые миграции, worker guards, profile допуска и GRANT не изменены.

[Общий PG-тест](../tests/logical-backup-restore-postgres.mjs) сохраняет сценарии57
и дополнительно выполняет их для58. В одноразовой58 созданы непустые payment
capture/history, незавершённый retirement request и completion. Только там
временно сдвигались часы; исходная функция восстановлена до dump. После restore
сверяются все строки, точный fingerprint, identity sequence и три роли.
Повтор completion не освобождает бюджет повторно, late write запрещён,
фото из исходной оплаты нельзя очистить, журналы остаются неизменяемыми.
Подмена раннего имени/хеша миграции при прежних count/max и изменение другой
части схемы отклоняются до реконструкции CHECK. Отдельная инъекция ошибки
после SQL подтверждает полный rollback реконструкции и неизменность всех строк.
Все17 проверок прошли.

## Свежая копия постоянного стенда

Источник первоначально был остановлен. Существующий prepare helper проверил
его сохранённые ID/name/image/label/loopback definition, запустил тот же контейнер,
сверил точную58 и обновил только изменившийся динамический localhost-порт.
До dump клиентов приложения не было; удерживалась существующая OS writer
блокировка. Дамп выполнен из экспортированного read-only Repeatable Read
snapshot. Исходные пароли ролей не экспортировались.

Новая цель — отдельный принадлежащий проверке PG18 контейнер с закреплённым
образом, tmpfs и loopback, без host mounts. Роли созданы с прежними атрибутами
и одноразовыми синтетическими паролями, ACL восстановлены из архива. Цель
удалена после повторной проверки ID/image/label. Результат:
