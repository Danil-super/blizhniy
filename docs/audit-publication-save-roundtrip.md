# Сохранение и оплата публикаций: локальная проверка 15.11.2026

## Исправление

Фабрики сохранения вакансий/заказов и услуг удерживали ссылку на переданный
snapshot. Если вызывающая сторона меняла его ID или revision во время загрузки
фотографии, последующее сохранение либо чтение результата использовало уже
изменённые значения. После принятия конфликта аналогичная ссылка сохранялась
на объект, возвращённый интерфейсу. Серверная проверка владельца при этом
сохранялась: это ошибка фиксации клиентской операции, а не доказанный обход ACL.

Теперь обе фабрики, как существующее сохранение объявления, фиксируют только
ID и revision. Принятие конфликта копирует revision, сохраняя первоначальный
ID редактирования. Новых API, зависимостей, миграций и прав нет. Проверены
вызывающие useWorkPublicationSave и useServicePublicationSave: их контракт
не изменён; uncertain/readback, последовательная загрузка, порядок фотографий
и запрет повторного неизвестного сохранения остаются прежними.

## Незакрытая ошибка React

Два предыдущих полных прогона дошли до последнего assertion без нарушения
финансовых инвариантов, но зарегистрировали один pageerror: React418/HTML.
Во время события открывалась страница редактирования заказа. Точная причина
и место несовпадения ещё не доказаны. Чтение той же формы отдельно, включая
задержку загрузки её JS, ошибку не воспроизвело. Последний полный прогон с
CDP-breakpoint перед исключением прошёл без pageerror; это может менять тайминг
и не является доказательством устранения гонки. Подавления ошибки нет.

Дополнительный полный прогон в17:30UTC также прошёл: вместо остановки CDP
в локальную копию React-чанка на границе тестового браузера добавлен только
сбор ожидаемого/фактического DOM перед штатным исключением. Проверено39
загрузок диагностического чанка, mismatches=0; исходники приложения и
assertions оператора не менялись. Три отдельных открытия формы с задержкой
её JS на1.5s также не дали ошибки. Следующий запуск с обычным React-чанком
снова достиг доставки отклика без новых pageerror, но остановился на
session429; он не считается полным успешным прогоном.

Ошибка остаётся открытой: следующий шаг — получить несовпавший DOM/Fiber при
повторении без остановки debugger. Этот документ не закрывает общую приёмку
крупного этапа или весь аудит. Настоящая TEST/fiscal ЮKassa, нагрузочная
приёмка, отложенная очистка media и production-проверки двух российских
серверов остаются отдельными задачами. Production, push и deploy не выполнялись.
