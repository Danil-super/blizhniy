# F11: единый справочник профессий

Работа только локально. Основа — `55a072b`. Нужны существующие таблицы/FK, без новых миграций, ролей, финансовых прав и production-операций.

## Контракт

1. Публичный PG read model отдаёт только активные `{id,slug,name,parent,active:true}`, не более 1000 записей; превышение лимита и ошибка БД не заменяются статическим массивом. `GET /api/reference/professions` — no-store, точный Host и метод, без query/body; ленивый runtime после проверки запроса. Клиент ограничивает время/объём ответа и проверяет DTO.
2. Primary-формы вакансии, заказа и анкеты используют этот список. Подпись поля — имя, выбранное значение — UUID. Свободный текст не превращается автоматически в первое совпадение при одинаковых именах. Загрузка/ошибка не стирает введённые поля; статические варианты остаются только в legacy-компоненте.
3. `professionId` — необязательное поле формы для совместимости со старыми клиентами. Когда оно передано, сервер разрешает ссылку по UUID; переданное имя не является полномочием. Старое имя без ID допустимо только при однозначном выборе, либо сохранении прежней ссылки владельца. Новое создание с отключённой ссылкой запрещено; текущую отключённую ссылку можно оставить в черновике, но нельзя использовать для нового размещения/отклика.
4. Private snapshot дополнен необязательным для старого wire `professionId`; новый сервер возвращает значение FK. Отображаемое имя читается по FK, в том числе после переименования/отключения. Изменение справочника само по себе не переписывает публикацию, revision, оплату и даты. Отключённое выбранное значение показывается явно, без подмены другим.
5. Public work/service карточки, анкеты для отклика, поиск, страницы профессий и sitemap получают текущие названия/профессии из PG. Переименование не скрывает действующую публикацию из-за сравнения старой JSON-подписи; отключение продолжает закрывать public/checkout eligibility. Для primary-страницы профессии фильтрация по UUID выполняется в SQL, legacy-путь сохранён.
6. Save/readback сравнивают все пользовательские поля. Различие отображаемого имени профессии допустимо только при одинаковом ненулевом валидном `professionId`; другая ссылка, цена, описание, фото или контакты не считаются тем же сохранением.
7. Новая metadata выдаётся четырьмя private API только при `X-Blizhniy-Profession-Refs: 1`; старые вкладки сохраняют прежнюю форму DTO. Этот заголовок не заменяет cookie, Origin или владение. Для новых возможностей и лимита подписи 200 нужен обновлённый клиент.

## Проверки

- RED/PG18: добавить, переименовать, отключить профессию; новая форма/старый черновик, публичная выдача, существующие публикации, неоплаченный checkout, снимок отклика; два одинаковых имени с разными ID; неизвестный/чужой publication owner; отсутствие изменений оплаты/дат/revision и границы 1000.
- Native: строгие DTO, query/method/Host до runtime, предел ответа, неверный UUID, stable-ID readback, клиентская валидация динамического поля без статического allowlist.
- Chromium: первичная загрузка и повтор после ошибки, поиск мышью/клавиатурой, добавление/rename/disable без правки data.ts, старое выбранное значение, сохранение других полей и защита при обрыве связи.
- Сохранить существующие assertions/guard. После проверок обновить общий план, Graphify и Code Graph того же проекта. Наличие кода не равно публикации или закрытию всего аудита.
