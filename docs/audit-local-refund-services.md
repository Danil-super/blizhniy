# Общий запуск локальных возвратов — 12.11.2026

`startLocalRefundServices` соединяет уже проверенные operator/worker runtime
и private IPC. Импорт не запускает службу, не читает окружение и не получает
новые права. Доверенный launcher явно передаёт фабрики обоих runtime,
создание private server, reporter и AbortSignal. Проверки физического
контейнера, TLS, роли, схемы, магазина и TEST остаются в прежних фабриках.

Сначала проходит preflight оператора, затем существующая worker service
проверяет обработчик. Её событие ready приходит до первого claim: только
тогда создаётся private server. После внешнего reporter повторно проверяется
отмена; закрытый сокет не выдаётся вызывающему коду как готовый.

Возвращаются socketPath, done (0 — штатная остановка,1 — отказ) и cached close.
Отмена закрывает приём команд и останавливает цикл без прерывания текущей
финансовой транзакции. Завершение дожидается worker и operator cleanup;
при отсутствии server оператор закрывается напрямую. Поздний результат
асинхронного создания ресурса также обязательно закрывается. Ошибки наружу
обезличены; автоматического повторного запуска/claim/команды нет.

Файл входит только в пакет worker. Operator artifact по-прежнему не содержит
worker service, отправителя или потребителей очередей. Старые роли,
fingerprints, миграции, границы sender и все прежние проверки не менялись.

## Проверка

Новый native-набор покрывает startup order, ошибки фабрик/preflight/server/
reporter, uncertainty, отмену до/во время старта, поздние handles, отмену во
время ready report, drain и единственный close. Плановое ревью выявило две
гонки отмены — добавлены тесты и проверки владения. Ревью реализации без
замечаний; дополнительную модель владелец пропустил.

Native2640/2640, PostgreSQL18.6 110/110, focused artifact/lifecycle9/9,
floor/types/lint прошли. Прежнее lint-предупреждение targetType сохранено.
Offline импорт пакета проверяет отсутствие сети, DB и запуска процессов.
Полный прежний PostgreSQL-сценарий сохранён без изменения утверждений.
Новый packaged coordinator проверяется с настоящими TLS/минимальными ролями,
двумя idle-рестартами, закрытием IPC и отсутствием оставшихся DB-соединений.
Отдельный non-idle сценарий создаёт оплаченное опубликованное объявление,
проводит approval через UDS до первого claim, затем проверяет единственный
возврат/эффект/уведомление и остановку. Провайдер синтетический.

## Подготовка установки на ручной стенд

Постоянная БД сохраняет прежние39 миграций и выключенный TLS; этот блок
не запускает её и не устанавливает новый код. Известная последовательность
следующего пакета:

1. Повторно доказать принадлежность контейнера/state, сверить живой журнал39
   и SHA256; сохранить закрытое восстановление перед изменениями.
2. Добавить только16 ранее подготовленных миграций до55, сохранить web-права;
   подготовить отдельные минимальные operator/worker роли и проверяемый TLS.
   Не повторять автоматически установку при несовпадении/неизвестном исходе.
3. Допуск точной55 уже согласован и сохранён в418470c:
   [просмотренный diff](review/local-refund-provider-launcher55.md),
   без автоматической установки миграций.
4. Подготовить устойчивый локальный provider-симулятор возвратов с сохранением
   idempotency между рестартами; реальный API и реальные деньги не использовать.
   Устойчивый provider сохранён в418470c; подключение к явному --refunds
   реализовано в [новом блоке](audit-local-refund-activation.md).
5. Передать отдельные проверенные фабрики новому coordinator, подключить
   socket к существующему proxy и согласованному UI-флагу; проверить browser
   approval/recovery, рестарт, отзыв доступа и остановку на ручном сайте.

Это порядок подготовки, а не готовый installer или разрешение на установку.
Пакет изменения постоянного стенда будет предъявлен конкретным diff после
проверок. Первый большой этап F02 ещё открыт; настоящая TEST/fiscal приёмка
и production не затронуты.
