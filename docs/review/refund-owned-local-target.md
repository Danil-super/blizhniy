## Изменение

Прежний createLocalRefundOperatorRuntime по-прежнему принимает только127.0.0.1/blizhniy_test; его отрицательная проверка prod-имени сохранена. Новый отдельный createLocalPrimaryRefundOperatorRuntime допускает фиксированное blizhniy_prod только после read-only доказательства: защищённый state текущего UID, существующие definition/live validators, точные container ID/name/image/project label, работающий контейнер и loopback-порт. Произвольного database override или environment bypass не добавлено.

Доступ к Docker закреплён за локальным /var/run/docker.sock; inspect и чтение фиксированного публичного сертификата выполняются без shell, с timeout/maxBuffer и без наследования credential environment. Импорт ничего не запускает. Секреты state не выводятся и не передаются Docker. Та же ssl.ca/rejectUnauthorized конфигурация, которая поступает в Pool, сравнивается с сертификатом проверенного контейнера. Файл CA не перечитывается после этой сверки; поэтому подмена пути между проверкой и подключением не меняет доверенные байты. Общая проверка TLS/роль/schema55/TEST-shop/live-admin и все прежние запреты остаются.

Same-UID код и администратор локального Docker — доверенная граница, а не изоляция от их компрометации. Пакет не даёт production-полномочий и не устанавливает новую роль. Builder копирует только read-only proof и прежний local-primary-config; автоматического installer/startup нет.
