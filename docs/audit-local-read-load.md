## Найденное и исправление

Отдельный резкий всплеск25 одновременных запросов поиска дал7 результатов и18
HTTP500. Это воспроизводимый отказ действующего допуска: максимум два
поисковых reader на процесс, чтобы оставить соединения для аккаунта.
Поднимать лимит/маскировать отказ успешной пустой выдачей нельзя.

У приложения отсутствовал общий экран восстановления; человек видел
стандартную ошибку Next.js. Новый `src/app/error.tsx` использует существующий
визуальный формат формы объявления: русское описание, повтор загрузки и
ссылка на главную. Ошибка не превращается в «ничего не найдено»; приватные
сообщения/SQL/error digest в UI не выводятся. Более близкий error boundary
формы объявления сохраняется. Ошибки root layout, обработчиков событий и
API этим boundary не перехватываются.

Сам допуск поиска и доля отказов во всплеске этим изменением не исправляются.
Для следующего этапа требуется отдельно сравнить bounded очередь/допуск
с действующими ограничениями и финансовым трафиком; изменение защищённых
ожиданий двух reader требует конкретного diff и review владельца.

## Воспроизводимость

Закрытые collector-файлы сохранены в
`~/.local/state/blizhniy/local-primary-private/measure-{read-baseline,read-100,search-burst}-20261115.mjs`.
Запускать последовательно verified Node22 с `--experimental-strip-types` из
текущего корня, только при запущенном собственном стенде3045. Они проверяют
состояние, label/image/container ID и loopback порт штатными helper проекта,
используют фиксированные публичные URL и локальный CA. Запусков build,
native suite, Chromium и других нагрузочных проверок одновременно с замером
не было. Собранные агрегаты не содержат аккаунтов, ID публикаций или cookies.

В реальном браузере вызов `reset()` оставлял прежний ошибочный RSC payload.
Поэтому кнопка выполняет `window.location.reload()` только по нажатию:
получает свежий GET того же документа и сохраняет параметры поиска в URL.
Автоматических повторов или повторов денежных POST нет.

Обоснование error boundary и reset:
[официальная документация Next15.5.28](https://github.com/vercel/next.js/blob/v15.5.28/docs/01-app/03-api-reference/03-file-conventions/error.mdx).
HTTP deadline задаётся AbortSignal, а не socket timeout:
[Node22.23.4 HTTP](https://github.com/nodejs/node/blob/v22.23.4/doc/api/http.md).
