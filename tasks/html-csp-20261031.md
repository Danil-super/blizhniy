# F16 — CSP для HTML

Основа `a24f5f1`. Только локальная реализация/проверки. RootLayout уже использует `connection()` и request headers: CSP nonce не переводит ранее статические страницы в новый режим. API уже имеет отдельный deny-all CSP, его не ослаблять.

## Контракт

- Уникальный 192-bit CSPRNG nonce для каждого SSR/Flight запроса; входящие CSP/x-nonce перезаписываются. CSP передаётся Next в request headers для автоматического nonce framework/RSC scripts и в HTML response. Не пропускать HTML по клиентскому prefetch header. Static/images/fonts/API/metadata исключить, не ломая cache immutable ресурсов.
- Production по умолчанию report-only; явный режим enforce после локальной приёмки. Неизвестный режим запрещён. Локальный primary стенд включает enforce для ручной/браузерной проверки. Script policy без unsafe-inline/unsafe-eval в production, script-src-attr none, strict-dynamic; object/base none, frame-ancestors self. Style unsafe-inline остаётся для существующих transforms/2GIS; это отдельное ограничение, не разрешение inline JS.
- Разрешены собственные ресурсы, data/blob images, существующие Turnstile и vendor-scoped 2GIS endpoints. Telegram/YooKassa выполняют обычную top-level navigation, не получают широкого connect/frame разрешения. Legacy origin добавляется только при реально выбранном legacy backend и валидном HTTPS origin. Не отправлять production ПД во внешние системы.
- CSP report endpoint: bounded body/deadline, same-origin admission, фиксированные allowlisted категории, частота логирования ограничена независимо от атакующих строк. Не хранить document/source/blocked URL, policy/nonce, samples, cookies/IP/персональные данные. Клиентский отчёт — недоверенное наблюдение, не подтверждение XSS.
- Report-only не выдаётся за enforced защиту production. Реальная CAPTCHA/2GIS/OIDC/provider приёмка с рабочими ключами и наблюдение до production enforcement остаются отдельными; локальные adapters не подменяют её.

## Проверки

RED на действительном HTML без CSP. Unit policy/middleware/report boundaries, реальный Chromium report/enforce, уникальность/совпадение nonce с SSR scripts, отказ выбранного клиентом nonce, injection probes, hydration/client navigation/404/mobile, сохранение API CSP/cache ресурсов. Существующие local recovery/avatar сценарии под enforce. Native, real PG/bootstrap, types/lint/floor/build. Графы только текущего корня; локальные коммиты, без push/deploy/новых grants/изменений guard.

## Результат — 01.11.2026

Реализованы nonce middleware, report-only/enforce policy, динамические loaders и JSON-LD, ограниченный приватный report collector. Next 15 скрывает/восстанавливает Flight headers, поэтому исправление malformed document-prefetch вынесено в локальный ingress; для production подготовлен Caddy template, прошедший изолированный caddy validate. На live ingress правило не применялось.

Native 2358/2358, PG/browser 137/137, bootstrap 349/349, types/lint/floor/build прошли. Chromium подтвердил enforce на 8 маршрутах/404/JSON-LD/mobile/клиентской навигации, отказ synthetic inline/onclick и отчёты204. Отдельный Next report-only процесс подтвердил наблюдение без блокировки; остановлен. Recovery и avatar UI прошли под enforce. Графы обновлены, окончательная сборка и локальный стенд готовы. Детали и границы: `docs/audit-html-csp.md`.

До production enforcement остаются live ingress/staging проверка и report-only наблюдение реальных Turnstile/2GIS/OIDC/payment сценариев. Это не утверждение о закрытии production-приёмки и всех уязвимостей. Push/deploy/production DB и права не менялись.
