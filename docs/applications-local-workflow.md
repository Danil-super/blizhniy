# Отклики: локальное завершение сценария, 26.10.2026

## Договор

- Только owned local PostgreSQL18/HTTPS; production, внешняя ЮKassa и LIVE не меняются.
- Вакансии и заказы: заполненная собственная анкета без модерации, сообщение,
  сохранение, тариф `job-response`/`job_response` из БД, локальная TEST-симуляция,
  независимая проверка capture и атомарная доставка владельцу публикации.
- Сумма фиксируется в неизменяемом намерении; duration=null, не фиктивный срок.
- Редактирование и отзыв разрешены только до оплаты/начала неизвестной оплаты;
  созданный/ожидающий/успешный платёж блокирует изменение купленной версии.
- Отзыв — отметка, не удаление истории. Оплаченные/доставленные данные неизменны.
- Открытие входящего `sent` один раз фиксирует `viewed` с CAS; неизвестный ответ
  требует чтения результата перед следующими изменениями.
- Приватные контакты доступны только участникам доставленного отклика, не каталогу.
- Сохранены cookie/CSRF, verified/nonblocked, ownership, действующие справочники,
  оплаченная живая цель, сроки/возвраты её размещения, CAS, дедупликация событий.
- Новые DDL/права — только отдельная явная локальная операция после проверок.

## Результат локального этапа

26.10.2026: native **1989/1989**, `check:fast` и production-build прошли.
Сохранено прежнее lint-предупреждение в `checkout-prerequisites.test.cjs`;
ошибок типов/lint нет. Новых исключений floor нет.

`check-local-application-payments.mjs`: **15 сценариев на PostgreSQL18** с
откатом синтетических записей, DDL и прав тестовой транзакции. Проверены оба
типа публикации, запрет доставки до capture, точный replay, отмена, CAS,
withdrawal/context/ACL, возврат размещения, изменение версии/справочников,
удаление цели, SQL-ошибка и истечение срока во время доставки.

`check-local-application-workflow-ui.mjs`: настоящий локальный HTTPS/PG,
два новых синтетических аккаунта, редактирование сообщения, TEST-оплата,
доставка, автоматический viewed, выбор исполнителя и одно уведомление,
отзыв неоплаченного отклика. Другая сессия PG действительно удерживала
**строку работодателя FOR UPDATE**: HTTP503, capture сохранён, доставки нет;
после освобождения блокировки повтор доставил отклик ровно один раз.
320/768/1024/1440, нет горизонтального переполнения/pageerror/внешних запросов;
axe serious/critical — 0 в проверенных областях оплаты и деталей отклика.
Это не аудит доступности всего сайта и не нагрузочный тест.

Независимое инженерное ревью выявило catch-all, превращавший временную
ошибку PG в «содержание изменилось». Исправлено: только доменные конфликты
становятся blocked; Busy/SQL ошибки пробрасываются и транзакция откатывается.
Шесть regression-тестов проходят; возврат catch-all намеренной мутацией
роняет три из них, после восстановления снова 6/6.

Согласованная **0030** применена отдельным операторским скриптом только к
owned loopback-БД: журнал30, SHA256
`539c6440e06d588a55dfa64c52c7d120342940e52603f68ec1e5e4b0c92a29fa`.
Новые права существующей роли: SELECT таблицы и INSERT ровно трёх полей

Стенд оставлен на `https://127.0.0.1:3045/__local`; health200. Синтетические
browser-фикстуры сохранены для просмотра. Production, SSH, внешняя ЮKassa,

Дополнительное ручное внешнее ревью **не выполнено**:

## Ограничения и воспроизведение

- Отзыв не освобождает прежний unique(applicant, publication): повторная заявка
  на ту же публикацию не появилась как новая неоговорённая функция.
- Подтверждённая отмена платежа разрешает правку/отзыв. Неизвестный исход не
  становится отменой по таймеру. Неудавшаяся доставка после capture не означает
  возврат денег: интерфейс показывает ожидание доставки, не предлагает платить заново.
- Исторический receipt сохраняется при возврате; уже раскрытые получателю
  контакты не «отзываются». Возврат не повторяет доставку или уведомления.
- Только локальный симулятор исполняет новую оплату отклика. Этот этап не
  подключает production checkout/webhook/reconciliation для откликов.

Команды с проверенным Node22 в PATH:

```sh
npm test
npm run check:fast
node --experimental-strip-types scripts/check-local-application-payments.mjs
node --experimental-strip-types scripts/check-local-application-workflow-ui.mjs
node --experimental-strip-types scripts/apply-local-application-withdrawals.mjs --plan
```

Два прежних standalone-checker `check-local-vacancy-payments.mjs` и
`check-local-work-request-payments.mjs` останавливаются на прежнем ожидании,
что некорректный телефон `123` можно сохранить как черновик. После ранее
заказанной валидации сервер отклоняет этот ввод при сохранении. Их ожидания
**не изменены/не пропущены**, весь старый checker не объявляется зелёным.
Текущие корректные публикации обоих типов проходят полную оплату и отклик
в новом PG-checker; browser дополнительно публикует заказ и вакансию.
