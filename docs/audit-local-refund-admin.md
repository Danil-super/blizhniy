## Интерфейс и неопределённый результат

Компактный журнал показывает сумму, дату, статус, причину и раскрываемые идентификаторы.50 строк внутри scroll-area; переход читает следующую порцию без бесконечного накопления DOM. Для полного возврата нужны причина до500 символов и явное подтверждение прекращения размещения. Сверка использует известную candidate/link; если исходный ответ потерян, можно ввести известный ID возврата из кабинета ЮKassa. Это GET уже созданного возврата, не повторная отправка денег.

До отправки финансовой команды её точный ID/payload сохраняется и прочитывается обратно из actor-scoped sessionStorage. Нельзя заменить неизвестную операцию новым ID. После reload нет автоматической отправки: доступны проверка прежнего решения или явный повтор той же команды. Approval readback сверяется с исходными payment/reason; закрытие записи происходит только после валидного ACK. Недоступное/повреждённое storage блокирует новую команду до её отправки. Session token в storage не попадает.

Авторизационный loading, отзыв admin и смена actor немедленно убирают приватный workspace. Cleanup отменяет ожидание/игнорирует поздние ответы; durable ID остаётся для прежнего actor. При timeout/disconnect оператор может ещё завершить транзакцию: это неизвестный результат, а не доказанный отказ, поэтому автоматического retry или замены ID нет. Штатные ограниченные GET-повторы транспортов сохраняются.
