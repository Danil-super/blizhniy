# Одна анкета в кабинете

Локально проверено 26.10.2026. Вкладка `/cabinet/specialist` сразу показывает
данные единственной анкеты, без списка материалов, «Подробнее» и кнопки
создания второй анкеты. Кнопка «Редактировать» открывает существующую форму
`/rabota/specialisty/anketa?draft=<id>`; сохранение возвращает к данным анкеты.
Если сервер подтвердил отсутствие анкеты, во вкладке открывается форма
первичного заполнения без дополнительного перехода и ссылки «назад» в ту же
вкладку. Содержимое ограничено `max-w-3xl` и выровнено по центру.

Имя и аватар берутся из текущего профиля того же аккаунта. Профессия, город,
адрес при наличии, стоимость, контакты и «О себе» — из сохранённой анкеты.
Прежние description/skills/experience отображаются через существующий
`specialistAbout`, без удаления старого текста. Готовность к откликам не
выдаётся за платную публикацию в каталоге.

## Почему без новой таблицы или API

Существующий `service_single_specialist_idx` в миграции0017 запрещает более
одной неудалённой анкеты одного владельца. Повторный create с другим ключом
возвращает существующую анкету без перезаписи полей; редактирование использует
тот же ID и CAS. Этот серверный договор не изменялся. Вкладка использует
существующие cookie-owner list/read и отдельный `SpecialistProfilePanel`;
списки ярмарки и рекламы остаются прежними.

Ошибка list/read не означает отсутствие анкеты: вместо формы создания
показываются ошибка и повторная загрузка. Неожиданные несколько результатов
или nextCursor тоже не приводят к молчаливому выбору произвольной анкеты.
Workspace разделён ключом владельца, скрыт/inert при временной проверке
входа; несовпадающий профиль не подставляется из исторического form.title.
