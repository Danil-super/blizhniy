# Профессия: обновление справочника и восстановление после отказа

15.11.2026. Локальный этап L26; без push/deploy/DDL/GRANT.

Проверен общий ProfessionSelect, который PrimaryProfessionSelect использует
в формах вакансии, заказа и анкеты. В активных primary-формах город уже
выбирается через DropdownSelect из предыдущего этапа. Отдельный legacy
CitySelectField этим исправлением не меняется.

Четыре новых теста воспроизвели следующие ошибки:

- Открытый список скрывался во время загрузки/отказа, но aria-expanded
  оставался true, а aria-activedescendant указывал на отсутствующий вариант.
- Enter во время обновления мог выбрать ранее подсвеченную профессию
  из старого массива: менялся UUID, хотя новый справочник ещё недоступен.
- Отказ загрузки также позволял заменить прежний выбранный UUID клавишей.
- Сообщение прежней ошибки оставалось после успешного повтора или
  показывало устаревшую причину вместо текущего результата справочника.

Видимость списка и связанные ARIA-состояния теперь вычисляются одним
popupOpen. Пока справочник не готов, выбор заблокирован, Enter не отправляет
форму, Escape/Tab закрывают намерение открыть список. Текущий UUID сохраняется;
проверки inactive/unavailable, дублей названий и customValidity не ослаблены.
Сообщение валидации выводит текущую причину и исчезает при восстановлении
допустимой выбранной профессии. Исправлен контраст подписи категории/slug
на фоне подсвеченного варианта; сама подпись сохранена.

## Доказательства

После исправления focused11/11, включая прежние проверки первичного UUID,
отключённой профессии, одинаковых названий и отсутствия legacy fallback,
прошли без изменения старых assertions. Native2804/2804 без skips,
floor/types/lint и build прошли; прежнее предупреждение targetType осталось.

Оператор scripts/check-local-profession-refresh.mjs проверяет реальную
compiled форму заказа на owned HTTPS-стенде. На320/768/1440 выбран ID,
подсвечен другой вариант, затем GET справочника задержан на границе браузера.
Во время loading и синтетического HTTP503 проверены закрытое ARIA-состояние,
отсутствие dangling ID, запрет выбора/implicit submit, текущая ошибка и
checkValidity=false. После «Повторить» выполняется настоящий локальный GET:
UUID прежний, checkValidity=true, старый alert/aria-invalid отсутствуют,
список снова открывается и закрывается клавиатурой.

Все три сценария прошли на build Xc9v1Wuwb0RpYKhDbZ8ml. Девять scoped axe
без serious/critical, pageerror/внешних запросов/записи публикаций нет.
Публикация не сохранялась, справочник и данные БД не изменялись. Полная
PostgreSQL-матрица для изменения отображения здесь повторно не заявляется.
Graphify и Code Graph обновлены для текущего корня; Gitleaks не нашёл
секретов в пяти изменённых/новых файлах. Исключений scanner не добавлялось.
