# Дополнение к PR130: готовность dev-формы регистрации

Статус: владелец одобрил точный patch и пакет выпуска 16.11.2026. Patch применён
после проверки в отдельной временной копии; байты кандидата совпадают.
Основание review — CONSTRAINTS.md:25:
«обоснованный рефакторинг требует явного review».

## Причина

На commit `e6a095c427d9e3e5a2cffd61f862824e88e0d87b` оба запуска CI
`43854023944` прошли 2817 native-тестов, затем остановились в первом
браузерном сценарии регистрации: `page.goto('/auth/local')`, 10000 ms.
Последующие ошибки `seedUser` — следствие отсутствия пользователя, которого
должен был создать этот сценарий. Они не являются 14 независимыми дефектами.

Текущая подготовка ожидает только API-route. Next dev компилирует страницу
регистрации при первом запросе. Чистая локальная копия исходного commit прошла
все 136 дочерних сценариев; её parent завершился ошибкой тайм-аута удаления
временного Docker-контейнера (контейнер затем удалился). Отдельное холодное
открытие на двух CPU заняло 7,6 s, включая 4,5 s компиляции. Это объясняет
уязвимость фикстуры к скорости runner, но не доказывает точное распределение
времени внутри неудачного CI: его compiler trace не сохранён.

## Точный кандидат

[Patch](registration-dev-readiness.patch) добавляет только три строки в
`tests/registration-web-integration.mjs`: комментарий и две проверки.

После готовности API существующий CA-validated `fetchLocal` открывает
`/auth/local` и требует HTTP200. Завершение компиляции должно уложиться в
существующий общий startup deadline 60 s. Затем идут прежние HTTP и browser
сценарии. Это подготовка собственного сервера разработки, не изменение
поведения production-приложения или проверка его производительности.

Сохранены browser/action/navigation timeout 10000 ms, timeout HTTP-helper
20000 ms, все прежние assertions, сценарии,
ограничение запросов своим origin, проверки TLS, CSRF, токенов и полномочий.
Отдельно владелец одобрил [общий бюджет набора180→240 s](postgres-suite-budget.md)
16.11.2026 после измеренного тайм-аута parent в CI; остальные границы сохранены.
Пропусков, retry, подавления ошибок и новых исключений floor нет.
При компиляции дольше 20 s helper по-прежнему завершится ошибкой.

## Проверки

- Кандидат на отдельной холодной копии с временной PostgreSQL 18.6:
  **137/137**, включая parent и cleanup, exit0, 109,9 s.
- Первый браузерный signup/подтверждение/replay: 2,6 s; остальные проверки
  входа, восстановления, прав и доступности также прошли.
- `git apply --check` успешен. Независимое read-only инженерное ревью
  конкретного patch не нашло нарушений контракта.
- Floor до применения был чистый. После применения floor и CI проверяются
  заново; прежний красный CI не выдаётся за успешный.

Остальные 12 PostgreSQL-наборов и сборка в этих двух CI не запускались после
первого отказа. Локальная проверка кандидата их не подменяет. Выпуск допустим
только после полного успешного Validate app и остальных обязательных gates
на окончательном commit; текущие красные PostgreSQL-проверки не исключаются.

## Решение о выпуске

Предлагается применить только приложенный patch и продолжить
[пакет выпуска PR130](production-test-release-20261116.md) после CI.
Этот пакет отдельно описывает два точечных допуска, согласованных владельцем 16.11.2026
для PR130: `DR-NO-INPUTS-PR130-20261116` для недоступного Dependency Review API
при неизменных зависимостях и `SELECTOR-BACKPORT-PR130-20261116` для прежнего
moderate version-based срабатывания с проверенным backport. Никакая другая
ошибка CI этим не разрешается. Workflows и guard данным дополнением не меняются.

Доставка исходников сохраняет production env/БД/ACL и отдельный TEST-worker.
Миграции0034+, локальные симуляторы и новые локальные режимы не включаются.
LIVE/реальные списания не включаются. Полный тест вакансий/заказов/откликов,
зависящих от нового runtime, требует отдельного плана включения; этот source
release не означает функционального равенства локального и рабочего стендов.
