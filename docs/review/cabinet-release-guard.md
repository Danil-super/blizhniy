# Выпуск локального кабинета: точечное обновление проверки worker

Подготовлено 28.10.2026 по поручению опубликовать новую версию кабинета. Рабочая версия до выпуска — bfde64d; локальные изменения сохранены коммитом 0d5fee9 и объединены с опубликованными исправлениями безопасности/производительности в 2f8b387.

## Конкретный diff для review владельца

[patch](cabinet-release-guard.patch), SHA256 `7394c71ca5780ed15f3dec96771f68a61374964a75a805fc3426f92058d2ed87`. Он относится к четырём перечисленным в patch файлам.

- Проверка принимает только прежние точные журналы 0024/0025 либо полный известный журнал 0001–0032 с совпадающими SHA256. Произвольные префиксы, промежуточная 0031 и неизвестные миграции не принимаются.
- Для 0032 финансовой роли разрешается дополнительно только SELECT `app.listing_blocks.listing_id`: обработчик должен учитывать блокировку объявления. Изменять блокировки, читать причины или получать новые UPDATE/INSERT/DELETE права он не сможет. Все прежние проверки memberships, ACL, EXECUTE, grant option и тел триггеров сохраняются.
- Offline-пакет worker включает точные источники новых миграций для проверки хешей. Никаких credentials в пакете нет.
- Известный результат `phone_required` добавлен в журнал обработчика; обязательность Telegram остаётся выключенной.

Изменение guard требует human review по CONSTRAINTS.md: «Изменения самого guard/workflows и semantic ослабление без изменения чисел обязательно проверяются человеком». До одобрения рабочую схему/guard не переключаем.

## Проверки

2078 native-тестов, 349 прежних PostgreSQL-проверок прошли. Отдельно прошла 21 проверка phone/schema0032: настоящий минимальный финансовый логин принимает точные права, отказывает при добавлении SELECT reason, изменении hash и неполном журнале. Типы/линтер без ошибок, одно прежнее warning. Production dependency audit — 0. Финальный build, браузер и CI проверяются перед публикацией.

## План выпуска

1. Сохранить защищённый application dump на российском VPS, сверить текущий журнал 0025 и точные хеши.
2. Одной транзакцией применить только добавочные 0026–0032 и точечные права из scripts/cabinet-release-plan.mjs. Существующие публикации, аккаунты, оплаты и сроки не переписываются. Никаких новых ролей или расширения прав назначения оплаты.
3. Сохранить и обновить только конфигурацию режима кабинета: postmoderation для российского postgres backend; LOCAL_PRIMARY не включать. Telegram available=false/required=false, LIVE выключен, ограничение TEST на прежний согласованный аккаунт сохраняется.
4. После CI опубликовать точный commit через штатный deploy/rollback. Сверить release SHA и хеши исходников с локальной версией, проверить кабинет пользователя/админку и публичные страницы.

## Намеренные различия сред

Локальный симулятор оплаты не переносится в production. Реальные списания не включаются. TEST-оплата объявлений остаётся в прежнем согласованном режиме, без обещания публикации. TEST-оплата вакансий/заказов/откликов пока реализована только локальным симулятором: на рабочем сайте соответствующее действие отключено с объяснением, без ссылки на /__local и без создания неплатёжного заказа. Черновики/редактирование/карточки/решения по существующим откликам/уведомления/админка доступны через российский backend. Telegram без Login-клиента также выключен в обеих средах. Это не выдаётся за работающий LIVE-платёжный контур.

## Откат

При ошибке приложения вернуть прежний release и сохранённые mode-настройки. Добавочные таблицы/историю не удалять. Смена рабочей схемы требует согласованного guard; прежний финансовый пакет до0032 не перезапускать на новом журнале. Обновлённый guard совместим с прежними 0024/0025. Перед обслуживанием worker сохраняются его unit/config; не включается постоянный poller или списание без отдельного решения.
