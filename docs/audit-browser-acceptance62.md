## Новый воспроизводимый сценарий сохранения входа

```sh
node --experimental-strip-types scripts/check-local-login-persistence.mjs
```

Он проверяет точный loopback origin и owned Docker fixture до чтения существующего
синтетического аккаунта. Создаёт закрытый временный persistent profile внутри
private local-state, блокирует внешние запросы страницы, сохраняет только безопасные
счётчики. В конце отзывает сессию теста и удаляет профиль; публикаций, оплат,
писем, DDL и GRANT нет. Перед отправкой формы включает cleanup даже на случай
успешного входа с потерянным ответом/неожиданным переходом.
Это проверяет чистый Chromium в пределах действующего срока сессии, не8 часов
ожидания, принудительное завершение ОС, очистку cookie пользователем или браузер
с расширениями. Настройки session/idle timeout не изменялись.

Использованы существующие fixture/config helpers и установленный Playwright.
Context7 отказал из-за месячной квоты; проверен официальный контракт
[persistent context](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)
и [общего cookie jar browser/request](https://playwright.dev/docs/api/class-apirequestcontext#api-request-context-cookie-management).
TLS-послабление существующего local browser harness ограничено точным HTTPS
loopback fixture; настройки TLS приложения/БД/production не менялись.
