# Критерии качества БЛИЖНЕГО

Пересмотрено 10.10.2026. Основание: владелец поручил выполнять программу L01–L30 поэтапно. Владелец продукта и решений об остаточном риске — Данил; инженерные проверки выполняет разработчик. Численные цели, ещё не измеренные инструментами, не выдаются за достигнутые или за работающие gates.

## Обязательный минимум — не ослаблять

- Подавления: не добавлять комментарии отключения type/lint/security/coverage checks ради зелёной проверки.
- Тесты: не пропускать, удалять или ослаблять проверки; обоснованный рефакторинг требует явного review, а не автоматического обхода guard.
- Реализация: не оставлять заглушки или пустые обработчики ошибок в завершённом инкременте.
- Секреты: не записывать реальные ключи, пароли, токены или персональные данные в Git, отчёты, CI и журналы.
- Договор: не убирать проверки, снижать пороги или добавлять исключения без согласования владельца и доказательства риска.
- Размещение: production ПД, файлы и их резервные копии остаются в подтверждённых российских контурах; внешние получатели отдельно проверяются.
- Операции: staging не получает production ПД и реальные платежи; покупка услуг и включение новых production-режимов требуют отдельного решения.

## Действующие механизмы

| Проверка | Правило | Реальная команда / механизм | Когда |
|---|---|---|---|
| Floor | Блокировать обнаруженное ослабление; ошибка выполнения не считается успехом | `npm run check:floor -- --base <ref>` | Локально перед commit; CI перед установкой dependencies |
| Types | Ошибки ≤ 0 | `npm run check:types` | Инкремент и CI |
| Lint | Ошибки ≤ 0; прежнее предупреждение не скрывать | `npm run lint` | Инкремент и CI |
| Native regression | Все тесты проходят, без новых пропусков | `npm test` | Контрольная точка и CI; focused tests в цикле RED → GREEN |
| Build | Успешная сборка | `npm run build` | Изменения приложения/зависимостей и CI |
| Secrets | Нет обнаруженных секретов | Gitleaks `detect --redact --exit-code=1` в security-checks workflow | Каждый release/PR, ошибка scanner блокирует |
| SAST | Нет блокирующих severe findings | Semgrep + `scripts/check-semgrep-report.mjs`, CodeQL + `scripts/check-codeql-report.mjs` | Каждый release/PR |
| Dependencies | Нет блокирующих high/critical production findings; учитывать и build/dev | `npm audit --omit=dev --audit-level=high`; Trivy и Dependency Review в workflows | Каждый release/PR |

Локальный `npm run check:fast` объединяет floor, types и lint; scanners остаются в CI. Быстрый diff guard не заменяет code review, Gitleaks или сканирование зависимостей. Он эвристический, для JS/TS: видит добавленные, удалённые, staged и untracked строки, а не все способы обхода; многострочные/динамические конструкции требуют review. Причины и пути выводятся без исходных строк. Exit 0 — чисто, 1 — нарушение, 2 — проверка невозможна. Для PR берётся merge base с base SHA, для push — before SHA; ручной CI без такого события проверяет последний commit относительно `HEAD^`. Локальный default — `origin/main`, не `HEAD`, иначе committed изменения не проверятся.

Изменение label правила может выглядеть как удаление; перенос assertion — как ослабление. Разбирать finding, не отключать gate. Изменения самого guard/workflows и semantic ослабление без изменения чисел обязательно проверяются человеком. GitHub branch protection этой работой не настроен; deploy уже зависит от validate/security/codeql.

## Baseline и ещё не включённые цели

Исходная точка `86e43c7`: native 997/997, PostgreSQL 18 integration 61/61, build 58 страниц; это факты предыдущей проверки, не измерение покрытия. Новый backend production-off, российская БД содержит только миграции 0001–0005, рабочий ready ещё зависит от Supabase. Подробности: `tasks/plan.md`, `tasks/todo.md`.

| Метрика / цель | Состояние механизма | Следующий пункт |
|---|---|---|
| Покрытие изменённой логики ≥ 80% | Baseline неизвестен; changed-line gate пока отсутствует. Финансовые и ownership ветки требуют дополнительных негативных/конкурентных проверок | L01 следующий инкремент |
| WCAG 2.2 AA, axe serious/critical ≤ 0 | Автоматический axe gate и ручной accessibility baseline ещё не подключены | L26 |
| LCP ≤ 2500 ms, INP ≤ 200 ms, CLS ≤ 0.1 на p75 | Нет достоверного field baseline; Lighthouse не измеряет field INP | L27 |
| Предварительно 100 активных пользователей, 30 минут | Не 100 RPS; read p95 ≤ 800 ms, write ≤ 1500 ms, auth ≤ 2000 ms, неожиданные 5xx < 0.5%. Профиль уточняется после baseline | L27 на staging, без реальных денег |
| RPO ≤ 1 h, RTO ≤ 4 h | Цели, не доказанные свойства тарифов; restore PG + media не проведён | L22 |
| SLO доступности ≥ 99.9% за 30 дней | Не доказан; бета 48–72 часа не подтверждает месячный SLO | L25/L30 |

Причины: покрытие проверяет новую логику, accessibility — доступность функций, CWV — скорость взаимодействия, профиль нагрузки — запас перед привлечением людей, RPO/RTO — ограничение потерь и простоя. Бюджет focused проверки — около 90 секунд; полный suite/build/scanners выполняются на контрольных точках и в CI, не после каждой строки. Пока нет измерения и реально воспроизводимого runner, цель не называется enforced gate и не понижается ради результата.

## Открытые риски и исключения

Полный audit ранее показал 9 пакетных предупреждений (7 high / 2 moderate), связанных с braces и selector-parser. Подробности, доказательства backport и срок пересмотра 14.10.2026: `docs/dependency-security.md`. Это открытый вопрос допуска build-контура, не разрешение игнорировать все high; production-only audit не доказывает безопасность всего проекта. В этой работе новых исключений не создано.

Исключение требует ID, правила и пути, обоснования, владельца, срока и явного согласования. Массовый запуск запрещён при незакрытом P0/P1: безопасность, деньги, приватность и критические сценарии блокируют независимо от ярлыка. Остальные риски допускаются только по решению владельца с ответственным и датой. Не обещать отсутствие всех возможных багов; выпускать после воспроизводимых проверок и наблюдаемой беты.
