Локально добавлены снятие, восстановление и мягкое удаление. Журнал0044 установлен только на проверенный ручной стенд; его схема теперь0001–0035+0041+0044. Добавлены SELECT журнала и INSERT пяти входных полей существующей runtime-роли. Новых прав UPDATE статуса, оплаты, срока или удаления исходных записей web-сервер не получил. Production не менялся.

## Поведение

- Карточки вакансий и заказов получили кнопку «Действия» с компактным модальным окном. «Редактировать» и «Посмотреть» сохранены. Для снятия/удаления требуется причина до500 символов; восстановление причины не требует.
- Снятие убирает действующую публикацию из каталога. Восстановление разрешено после собственного снятия и только в пределах исходного оплаченного периода. Удаление скрывает карточку и публичную страницу, сохраняя форму, фотографии, оплату, отклики и историю.
- Восстановление требует единственного исходного fulfillment для текущих owner/type/period и оплаты `succeeded`. Истёкший или возвращённый период, отключённая профессия/несогласованный город, отклонение модерации и выбранный исполнитель препятствуют восстановлению. Действующая проверка подтверждённого телефона сохраняется.
- Незавершённая оплата размещения блокирует изменение. Также блокируют созданные/ожидающие оплаты откликов и подтверждённые оплаты ещё не доставленных откликов: изменение версии заказа не должно лишить специалиста оплаченной доставки.
- Каждая операция имеет постоянный UUID и ожидаемую bigint-версию. После потери HTTP/COMMIT ответа повтор использует тот же запрос; прежнее решение читается до новой вставки, включая удалённую карточку. Повтор с другой причиной/владельцем/версией не принимается.

## Границы и атомарность

API использует существующие cookie, Origin/CSRF, trusted ingress и rate limit. Клиент не может назначать owner, paid/status/period/result или время события. SQL независимо проверяет текущую сессию и владение. User/session → финансовые строки → work, новые переходы к ресурсам — NOWAIT, с повторной проверкой срока сессии.

BEFORE INSERT только проверяет/блокирует/готовит журнал. Фактический UPDATE публикации выполняется AFTER успешной вставки, в той же транзакции. Это устраняет найденный и воспроизведённый обход `INSERT ... ON CONFLICT DO NOTHING`, при котором публикация могла измениться без записи события. При ошибке родительского UPDATE запись журнала также откатывается.

Окно управления доступно только при серверном local-v1 флаге для `https://127.0.0.1:3045`; по умолчанию функция выключена. Авторизованный HTTP не получает прямых финансовых прав. Новый лог не удаляется при откате к прежнему коду.

## Компенсации

0045 проверена на одноразовой PostgreSQL, но не установлена на ручной стенд. Она дополняет private источник0043 первым достоверным снятием/удалением **заказа** владельцем после доставки отклика. Восстановление заказа не стирает это событие. Просмотр до/в момент закрытия исключает компенсацию; поздний просмотр сохраняет ранее возникшее основание. У вакансии снятие само по себе не становится этим основанием.

Прежние cases не переписываются. Сумма остаётся полной и исходной; часть финансовой отправки/GET-сверки/очереди и уведомлений ещё не активирована. Настоящие операции ЮKassa не выполнялись.
