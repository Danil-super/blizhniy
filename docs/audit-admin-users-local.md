## Исправление

Настоящий PostgreSQL admin раньше получал403 от Supabase `/api/admin/users`.
Теперь primary экран `/admin/users` использует POST `/api/admin/user-directory`:
каноническая HttpOnly cookie, текущая подтверждённая незаблокированная app-сессия,
совпадение `expectedAdminId`, роль admin и повторная проверка сессии перед COMMIT.
Legacy UI/API сохранены только для legacy-режима; loading/anonymous primary не
переключаются на старую авторизацию.

Выборка возвращает только ID, имя, email, телефон профиля, текущую роль, блокировку,
подтверждение email и регистрацию. Ни profile JSON, ни пароли, токены, аватар,
адрес организации, платёжные данные не выдаются. Телефон не обозначается как
подтверждённый; «Активен» означает подтверждённый email и отсутствие блокировки.
В текущей модели есть только user/admin: анкета специалиста или организации не
становится дополнительной авторизационной ролью.

Поиск по имени/email/телефону/ID — буквальная регистронезависимая подстрока,
SQL-параметры. Фильтры: user/admin и active/blocked/pending email. Ответ до25 строк;
26-я определяет продолжение. Курсор `(created_at,id)` сохраняет все6 микросекунд,
сортировка стабильна при одинаковых датах. Ответы и ошибки no-store, лимитер общий.
В журналах только request ID, статус, длительность и безопасный код.

Интерфейс: адаптивные строки, подписанные контакты, цветные статусы, поиск/фильтры,
обновление, следующие25 и начало списка. Новые параметры и смена администратора
размонтируют прежний reader; cleanup отменяет запрос и игнорирует поздний ответ.
Отказ доступа инициирует перепроверку авторизации. Сбой не изображается пустой БД.
