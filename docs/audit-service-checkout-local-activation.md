## Приёмка установленной композиции

Настоящий Chromium → session HTTP → runtime PostgreSQL → локальный provider →
operator/worker/private socket и очередь рекламы. Создан только синтетический
участник, использован существующий администратор. Подтверждённый телефон
участника является fixture, реальный Telegram здесь не проходился.

- Одна подготовка рекламы отменена до anchor, история сохранена без оплаты.
- Ярмарка: модерация, показанный тариф/конкретное событие, оплата и публикация
  до точного окончания события по Москве; полный возврат через админку снимает
  карточку и создаёт единственные provider refund/effect/уведомление.
- Семь последовательных рекламных оплат: первые пять опубликованы, шестая и
  седьмая ожидают без receipt/потери срока. После возврата первой очередь
  публикует шестую; седьмая её не обходит. Срок шестой начинается фактически
  при появлении места. Возврат седьмой не создаёт публикацию.
- Итого9 подготовок,7 receipts,3 полных возврата/эффекта/уведомления.
  Сохранены исходные body hashes и условия события. Пять синтетических
  рекламных размещений остаются активны для ручного просмотра, старые карточки
  для освобождения места не менялись. Внешних запросов браузера/pageerror нет.
- После остановки финансовых соединений0. После перезапуска snapshot SHA256
  `bedb132287d411fc031c80389d389af8093d7ee8f18fddea1be3b07a4def0042`
