# Отклики, бронирования и уведомления — L15

18.10.2026. Продолжение утверждённого полного переноса, не новый набор функций. Подготовлена только добавочная схема0018 и явные минимальные grants; рабочая БД остаётся на0017 до отдельного согласования. Наличие таблиц само по себе не означает готовый пользовательский процесс.

## Сохраняемый контракт

| Часть | Данные и поведение | Граница доступа |
|---|---|---|
| Отклики | Одна запись заявителя на вакансию/заказ, точные revisions цели и анкеты, серверный snapshot анкеты и сообщение. Начальное состояние pending_payment/unpaid. Получатель видит доставленный оплаченный отклик, затем viewed/selected/rejected | Текущая cookie-сессия заявителя или владельца цели, не переданный userId/Bearer; не сам себе. Клиент не назначает оплату/отправку |
| Бронь | Жильё: период до30 ночей, pending и accepted блокируют пересечение, день выезда свободен. Поход: дату задаёт объявление, места занимают accepted. Цена/доступность рассчитываются сервером по текущей публикации; повтор использует стабильный intent | Гость или владелец объявления, не посторонний читатель. Принятие/отказ владельцем при текущем состоянии и блокировке родительской строки; клиент не меняет сумму, даты или гостя |
| Уведомления | Частный inbox, уникальный event на получателя, категории/тон/переход только в кабинет, read/dismiss вместо hard delete | Создание только доверенными предметными операциями в той же транзакции. Чтение/отметки владельцем inbox; не произвольная отправка чужому аккаунту |

Будущие repository/API/UI должны сохранить эти правила под текущим user→session→resource transaction, exact string bigint CAS, bounded bodies/pages и readback неизвестного COMMIT. Публичная доступность брони не раскрывает гостя, цену или private snapshot. Создание/решение и уведомления должны быть атомарными, без финансовых флагов из браузера. SMTP-рассылки уведомлений и новые платные услуги этим этапом не включаются.

## Схема и оператор

`applications`, `booking_requests`, `notifications` — только новые частные таблицы с FK/индексами/конечными состояниями. Публикации, пользователи и первые17 миграций не изменяются. Цена брони — конечный numeric(20,2), snapshot ограничен16KiB, ключи намерений и событий уникальны. Принятое решение требует непустого decided_at; stay требует непустого end_date, а не SQL UNKNOWN. Проверка сначала воспроизвела NULL-лазейку и после исправления проходит.

Команды: `node --experimental-strip-types scripts/bootstrap-postgres.mjs --plan-interactions` и отдельный `--apply-interactions HOST:DATABASE`; grants: `node --experimental-strip-types scripts/grant-interactions.mjs --plan | --apply HOST:DATABASE`. Только явный оператор после разрешения, не startup/deploy. Default и прежние opt-in планы сохраняют прежнюю длину и SHA. Down берёт exclusive lock и отказывается при любой строке новых таблиц; накопленные данные не удаляются.

Runtime получает SELECT3 и перечисленные INSERT-поля. UPDATE откликов — сообщение/snapshot/references/revision/status, но не идентичность, is_paid, sent_at или timestamps создания; SQL state constraint не допускает unpaid sent/selected. UPDATE брони — status/decided_at/revision/updated_at, не цена/даты/гость. UPDATE inbox — read_at/dismissed_at, не получатель/текст/event. Нет hard DELETE/TRUNCATE/TRIGGER/REFERENCES/MAINTAIN, grant options или финансовых EXECUTE. Реализация guarded queries всё равно обязательна: колоночные grants не заменяют проверку предметного владельца.

Общая проверка точечных таблиц вынесена из service-grant оператора в `operator-table-grants.mjs`, чтобы не копировать политику для0018. Прежний service-план остаётся точным17 и использует тот же проверенный алгоритм. Табличные/колоночные SQL identifiers дополнительно проверяются до запроса; mismatch history/target/role/остаточных прав отказывает, неизвестный COMMIT не повторяется.

## Проверки и следующие шаги

Native1464/1464, plan/CLI/grant focused5/5, types/lint/floor без ошибок (старое checkout warning сохранено). Runtime приложения не менялся после предыдущей успешной build63. Инверсия проверки operator identifier поймана тестом до первого SQL, затем восстановлена и focused2/2. Не использовались production ПД, живые платежи или чужие контейнеры. Непроверенные метрики покрытия/нагрузки не выдаются за результат.

Следующие срезы: guarded repositories и межпользовательские конкурентные тесты → cookie HTTP → реальные формы откликов, действия владельца и inbox → разрешённое применение0018/grants → CI/VPS smoke двух независимых синтетических пользователей. Платёжное исполнение, публикация и история оплаты остаются L17–L20 и требуют своего защищённого финансового контракта. До завершения всего пути L15 не закрыт.
