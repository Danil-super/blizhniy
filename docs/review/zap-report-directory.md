# S02: каталог отчётов OWASP ZAP

Кандидат для review владельца; `.github/workflows/zap-baseline.yml` пока не изменён.
Точный diff: [zap-report-directory.patch](zap-report-directory.patch).

## Ошибка и результат

Отчёт аудита фиксирует Permission denied для `/zap/wrk/zap.yaml` и
`/zap/wrk/zap-report.html` в запуске43849886145. Нынешний workflow монтирует
весь checkout, принадлежащий runner, а ZAP запускается своим nonroot-пользователем.
Кандидат монтирует только отдельный каталог `$RUNNER_TEMP/zap-reports`.

Существующий шаг подготовки создаёт каталог с2770, записывает его путь в
`GITHUB_ENV`. Контейнер сохраняет стандартные пользователя и команду образа,
получая только дополнительную группу runner. Setgid сохраняет эту группу у
создаваемых файлов; runner может прочитать отчёты для summary/upload.
Checkout, ключи и остальные каталоги в контейнер не передаются.

Пути summary и трёх artifacts используют тот же `ZAP_REPORT_DIR`.
Не меняются цель сканирования, аргументы baseline,25минут job,
`if-no-files-found:error`,14дней хранения и завершающий check-zap-result.sh.
Коды1/2/3/неизвестный и отсутствие любого непустого отчёта сохраняют failure.
Правила находок не исключаются; предупреждения не превращаются в success.

## Проверки

- YAML разобран; bash-синтаксис всех run-блоков проверен. Реальное выполнение
  шага подготовки создало каталог2770 и передало правильный путь.
- На локальном контейнере Python сUID65534/GID65534 воспроизведён отказ записи.
  Добавление группы хоста разрешило запись трёх синтетических отчётов;
  группа файлов унаследована и чтение с хоста прошло. Это проверка прав,
  а не сканирование ZAP.
- Существующий `scripts/test-check-zap-result.sh` прошёл. Дополнительно
  проверена та же защита на файлах, созданных nonroot-контейнером.
- Независимое read-only ревью обнаружило недоступный `runner` context в
  первоначальном job.env; кандидат исправлен на RUNNER_TEMP/GITHUB_ENV.
  Повторное ревью не нашло других конкретных проблем.
- Настоящий ZAP stable `sha256:9624669db72f54d86c4b46a7064518bd9bf79d8c61a4c31befa9923489f328af`
  выполнил кандидат на отдельном синтетическом HTTP-сервере в Docker без
  публикации портов хоста. Получены HTML66697байт, JSON22652байт и MD19961байт;
  runner прочитал каждый файл. Семь ожидаемых групп WARN у страницы без
  защитных заголовков дали scanner2 и gate1: предупреждения не пропущены.
  Это предупреждения синтетической страницы, не находки рабочего сайта.
- Отдельная попытка этого же кандидата против рабочего домена завершилась
  scanner3: Remote host terminated the handshake. Gate вернул1 за отсутствие
  отчётов. Успехом и результатом аудита production это не считается.
  Нужен запуск из GitHub после review; загрузка artifacts и разбор находок
  рабочего релиза ещё впереди. S02 пока закрыт только в части локальной
  проверки прав, а не динамической приёмки production.

### Дополнительная проверка 17.11.2026

Тот же отдельный каталог/setgid/дополнительная группа проверены настоящим
nonroot ZAP на действующем локальном HTTPS-приложении, затем повторно после
исправлений. Checkout и закрытые настройки контейнеру не передавались.
В обоих запусках все три отчёта непустые и доступны хосту; scanner2 и gate1
сохранили отказ из-за предупреждений. Между запусками устранены отсутствие CSP
у неизвестного API и `eval` в плеере анимации; остальные предупреждения не скрыты.
Подробнее — [локальная приёмка безопасности](../audit-launch-security-performance.md).
Точный patch выше всё ещё применим (`git apply --check`); workflow пока не изменён.
`scripts/test-check-zap-result.sh` снова прошёл, правила findings/upload не менялись.
Предлагаемый допуск — применить только этот patch локально. Он не включает push,
запуск GitHub Actions, изменение CSP production или публикацию сайта.
