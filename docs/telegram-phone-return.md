# Возврат подтверждения телефона

29.10.2026 исправлен возврат Telegram Login на рабочем сайте. Попытки оставались pending: callback отклонялся ещё до обращения к хранилищу state.

Отдельная настоящая standalone-сборка Next15.5.28 показала `NextRequest.url` с authority `https://localhost:<port>` при слушателе на 127.0.0.1 и сохранённом внешнем Host. Canonicalizer принимал только `https://127.0.0.1:3000`. Теперь допускаются ровно оба имени фиксированного loopback-слушателя на3000, при прежних обязательных Host рабочего домена, X-Forwarded-Proto=https, единственном доверенном X-Real-IP, GET и точном callback path. X-Forwarded-Host не используется. State, сессия, PKCE, nonce и проверка подписи не изменены. Новый regression сначала воспроизвёл отказ, затем прошёл; прежние негативные проверки сохранены.

После подтверждённого сервером номера показывается «Телефон успешно подтверждён», окно закрывается через1,5сек. Если сохранённый номер пуст или совпадает, завершение выполняется автоматически. Замена другого сохранённого номера требует отдельного согласия. Неопределённый ответ подтверждения восстанавливается только чтением той же попытки, без автоматического повтора записи.

Исходная вкладка проверяет подтверждение через session-bound review/status, затем обновляет только телефон в профиле и несохранённой форме. Сообщение между окнами само по себе не считается подтверждением. Проверяются origin/source для postMessage и attemptId; BroadcastChannel используется при разрыве opener. При недоступном BroadcastChannel дополнительно проверяется закрытое окно каждые5сек, только в видимой вкладке и в пределах десятиминутной попытки. Уход в фон или временное auth-loading не уничтожает попытку. Идентификатор окна хранится только в памяти вкладки; номера и credentials в браузерное хранилище не записываются. Смена владельца и истечение срока закрывают старое окно.

Браузерная проверка: `node --experimental-strip-types scripts/check-telegram-phone-popup.mjs` на собственном локальном стенде. HTTP-ответы провайдера и phone/profile API заменены явными fixtures: без реального Telegram exchange, записи номера, SMTP или production данных. Проверяются автоматический успех, согласие на замену, сохранение черновых полей, COOP и недоступный BroadcastChannel. Дополнительно выполняются настоящие 22 проверки настоящего PostgreSQL из telegram-phone-postgres-integration и прежний local-return browser regression. Настоящую авторизацию своего Telegram-аккаунта завершает владелец номера.

Схема БД, grants, платёжные режимы и маршрутизация двух российских серверов не меняются. Выпуск — через обязательный CI, готовый artifact, postchecks и подтверждение host watchdog.
