# Проверка нового ограничения сообщения — 500 символов

26.10.2026. По запросу владельца отклик ограничивается 500 символами на клиенте
и сервере. Старое ожидание приёма 3000 символов противоречит новому правилу.

Предлагается разрешить в guard только одну точную пару строк файла
`tests/application-contract.test.mjs`, каждая должна встретиться в diff один раз:

```diff
- assert.equal(parseApplicationCreate({...create,message:'x'.repeat(3000)}).message.length,3000);
+ assert.equal(parseApplicationCreate({...create,message:'x'.repeat(500)}).message.length,500);
```

Новые отдельные assertions отклоняют 501 символ и при создании, и при
редактировании. Прежние проверки 3001 символа, Unicode, управляющих знаков,
обязательного envelope, CAS и запрета клиентских платёжных полей остаются.
Чтение исторических сообщений до 3000 символов сохраняется; они не обрезаются.

Владелец 26.10.2026 одобрил точечную замену; patch применён. `application-message-limit.patch` меняет
только точную пару before/after в существующем механизме reviewed replacements.
Никаких общих исключений путей, удаления тестов или ослабления других правил.
