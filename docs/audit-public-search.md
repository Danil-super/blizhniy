# F12 — поиск без переноса всего каталога в приложение

Исправление подготовлено только локально, основа `774ee4f`. Первичный поиск PostgreSQL теперь выбирает совпадающие публичные записи в SQL, затем материализует одну страницу через существующие публичные DTO. Legacy-ветка остаётся отдельной. Новых миграций, привилегий, зависимостей и production-операций нет.

## Поведение и ограничения

Сохраняются буквальная подстрока без учёта регистра, выбранный город, 24 результата и прежний приоритет разделов. `%`, `_`, `!` и обратная косая ищутся буквально. Unicode lower проверен на кириллице, латинице, İ и греческой сигме. Название категории объявления берётся из актуального справочника БД, вместо ошибочного статического fallback. Поиск не обращается к контактам и скрытым полям анкеты.

SQL использует те же public gates, что карточки: текущая ревизия/политика публикации, подтверждённая оплата, срок, автор, активные справочники и допустимые фотографии. Последующее преобразование DTO сохраняет дополнительную проверку полей. Испорченная запись пропускается; окно пополняется без раскрытия её содержимого или специальной ошибки по совпавшему скрытому тексту.

Пять физических источников покрывают семь видов результатов. Ограниченные MATERIALIZED CTE читаются в порядке разделов и получают остаток общего окна в 25 кандидатов. После заполнения окна оставшиеся источники не исполняются. Для обратного перехода меняются и порядок источников, и внутренние sortkeys.

«Далее/Назад» несут курсор по последней/первой показанной публичной записи, с точностью timestamps до микросекунд. Курсор связан с запросом и городом, не содержит отклонённых ID и не предоставляет прав. Все его значения, как и строка поиска, передаются параметрами. Старый числовой `page` 1–1000 поддерживается через проверку действительного префикса под тем же ресурсным бюджетом. Произвольный глубокий переход без курсора может исчерпать бюджет; обычная навигация этого обхода не выполняет. Изменения между разными запросами страниц не заморожены: удалённая/заблокированная запись исчезает, новые публикации видны при обновлении поиска.

Один запрос использует REPEATABLE READ READ ONLY snapshot для выбора и материализации. Общий срок 5 секунд включает холодную инициализацию, ожидание pool, BEGIN, SQL и COMMIT. Driver query_timeout и серверные statement_timeout/transaction_timeout дополняют общий таймер. При ошибке соединение уничтожается; просроченный поздний checkout SQL не запускает. Два search leases на процесс ограничивают конкуренцию, не увеличивая общий pool. Lease при незавершённом checkout/инициализации удерживается до фактического завершения. Ограничения всей операции: 25 100 кандидатов и 16 MiB сериализованных строк. Ошибка ресурса не превращается в успешный пустой результат. Старые пишущие транзакции не получают новых повторов/таймаутов.

## Измерения, 31.10.2026

Собственная disposable PG18.6: 1 CPU, 512 MiB; 25 000 корректных публикаций, по 5000 пяти видов. Перед обоими алгоритмами один прогрев. Старый алгоритм: три отсчёта, медиана и диапазон; новый: 20 отсчётов, p95. Сравниваются операции stores, а не HTTP/браузер. Для глубокой страницы старый числовой переход сравнивается с новым публичным курсором. Идентичность результатов проверяется на каждом отсчёте. Счётчик чтений учитывает запросы данных; служебные BEGIN, установку таймаутов и COMMIT он не включает.

| Случай | Старый: медиана, мс | Новый: p95, мс | Строки БД → приложение, старый / новый | Чтения, старый / новый |
|---|---:|---:|---:|---:|
| Популярный, первая страница | 49,0 | 33,0 | 100 / 50 | 1 / 2 |
| Нет совпадения | 9625,9 | 54,0 | 25 000 / 0 | 255 / 1 |
| Страница 1000 | 9484,2 | 20,0 | 24 100 / 50 | 245 / 2 |

Это локальная синтетика, не production p95, field CWV или доказательство цели 100 активных пользователей / 30 минут. Два параллельных чтения (пустой поиск и глубокая страница) завершились за 62,7 мс. Полные EXPLAIN ANALYZE BUFFERS, счётчики, SHA256 фактически исполненного SQL и исходные условия — [search-20261031.json](performance/search-20261031.json).

| Попытка | Измерение | Решение |
|---|---|---|
| SQL filters + общий UNION/sort | Популярный p95 105,5 мс; глобальный sort принимает 25 000 строк; отсутствующий запрос p95 49,2 мс | Доработать: первое окно не должно читать все разделы |
| Остаточный LIMIT источников | Популярный p95 33,0 мс; глобальный sort принимает 25 строк, следующие источники имеют 0 loops. SQL execution 99,3 → 24,8 мс | Сохранено; выигрыш значительно больше вариации |
| Trigram index/cache/увеличение pool | Не выполнялись: текущие измерения не обосновывают дополнительные DDL/стратегию инвалидирования | Не добавлены |

Общее время первого экспериментального runner превысило его функциональный лимит 90 секунд. Эксперимент вынесен в отдельный opt-in top-level с бюджетом 300 секунд; функциональные проверки сохранили 90 секунд. Редких старых отсчётов недостаточно для p95 — поэтому для них показана медиана.

## Воспроизведение

```sh
npm test
npm run check:types
npm run lint
npm run check:floor -- --base 774ee4f
node --experimental-strip-types --test tests/primary-search-postgres-integration.mjs
BLIZHNIY_SEARCH_BENCHMARK=1 node --experimental-strip-types --test tests/primary-search-postgres-integration.mjs
node --experimental-strip-types --test tests/postgres-integration.mjs
node --experimental-strip-types --test tests/bootstrap-postgres-integration.mjs
npm run build
# После запуска собственной локальной сборки:
node --experimental-strip-types scripts/check-local-public-search.mjs
```

Общие PostgreSQL/browser runners и build выполняются последовательно: они используют общий `.next`. Измерение скорости выполняется отдельно от тяжёлого native/build прогона. Браузерный сценарий создаёт только случайные синтетические данные в проверенном собственном loopback-контейнере и удаляет только их. Chrome DevTools MCP недоступен в сессии; используется изолированный Playwright Chromium.

## Результат проверок

- Native: 2274/2274, без пропусков.
- Новый настоящий PostgreSQL runner: 18/18; все виды и public gates, Unicode/LIKE, mapper refill, стабильные UUID/microseconds, forward/reverse через смешанные ветки 2/3, 4/5 и справочники 6/7, SQL-looking строки, read-only snapshot, прекращение pg_sleep и новое соединение.
- Строгий контракт/runtime admission и deadline проверены native-сценариями, включая поздний checkout, холодный initializer и запрет использования завершённой транзакции.
- Общий PostgreSQL/browser runner: 137/137; bootstrap/ACL/payment: 349/349.
- Types, lint, floor и production build прошли; единственное lint-предупреждение — прежний `targetType` в checkout-prerequisites.test.cjs.
- Изолированный Chromium: 24/24/2 результатов, курсоры вперёд/назад, недопустимая запись перед страницей, скрытый черновик, города, буквальные wildcard-символы, 320/768/1440 px. Нет page errors, внешних запросов и 5xx. Скриншоты desktop/mobile просмотрены.
- Graphify и Code Graph обновлены для текущего корня. Финальная сборка запущена на `https://127.0.0.1:3045`; `/api/health` отвечает 200.

Инженерное ревью выявило ошибки границ страниц при недопустимых DTO, неполный deadline и необходимость удержания leases до позднего cleanup; они исправлены и покрыты regression. Финальный разбор реализации и оптимизации не выявил новых воспроизводимых замечаний. Дополнительную проверку другой моделью владелец пропустил. Остальные пункты аудита сохраняют свой статус.
