# Исходный дедлайн публичного поиска

15.11.2026. Только локальная разработка. При разборе всплеска поиска
независимое ревью обнаружило отдельную ошибку: относительный остаток срока
передавался в store, затем БД заново вычисляла `now + timeoutMs`. Время
проверки входа/курсора между слоями незаметно добавлялось к общему сроку.

Runtime теперь передаёт исходный absolute monotonic deadline через store
до `PostgresDatabase.readTransaction`. Новый необязательный параметр только
сокращает прежний timeout, не увеличивает его. Неверный deadline отклоняется
до checkout; уже истёкший освобождает admission без обращения к pool.
При позднем checkout перед BEGIN проверяются часы, даже если timer callback
ещё не выполнился. Timer и per-query budget используют тот же дедлайн.
Обычная write transaction не изменена. Вызовы readTransaction без нового
параметра сохраняют прежний относительный бюджет.

Восемь новых DB-тестов дали RED на исходной реализации; после исправления
они и прежние проверки прошли. Дополнительно проверена передача значения
через search store и освобождение admission при раннем отказе. На настоящей
временной PG18 проверен `pg_sleep(1)` с относительным1000ms и исходным
absolute100ms: запрос прекращён раньше700ms, callback один, следующий
checkout исправен. Полный PostgreSQL search suite19/19.

До одобрения native-регрессия рабочего дерева2784/2784 без skips
включала6 тестов ещё не активированного текстового кандидата очереди. Fast прошёл; прежнее предупреждение
`targetType` сохранено. Кандидат старого contract suite12/12 и TypeScript с
его runtime, наложенным в памяти, прошли отдельно. Gitleaks не нашёл секретов
в14 изменённых/новых файлах; новых исключений scanner нет.
