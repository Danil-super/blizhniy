# F08: сверка схемы58 и файлов — 15.11.2026

Исправлен воспроизводимый отказ операторской команды после перехода local57→58:
раньше она всегда требовала journal57 и сравнивала бюджет со всеми metadata,
включая завершённые terminal tombstones. Теперь допускаются только полный
исходный journal57 либо полный local58 с SHA256 и прежним exact fingerprint.
Финансовые guards, миграции, роли и GRANT не изменяются.

## SQL-сверка

[readMediaRetentionInventory](../scripts/media-retention-inventory.mjs) сохраняет
прежний default57 и его проверки. Явный режим58 дополнительно учитывает:

- два новых FK к media и неизменяемую историю ссылок/снимков оплаты;
- pending/completed retirement и время последнего наблюдения;
- фактически начисленные owner/global bytes/objects, исключая только completion.

Pending request остаётся начисленным. Metadata/intent tombstones не удаляются.
Версия2 отчёта отличает общий объём metadata от начисленного; историческая ссылка
не теряется после удаления текущей photo FK. Ограничения:10000 media,32MiB
текущих документов,1000000 событий журнала, прежний общий5s read-only deadline.
Неизвестный FK, испорченный учёт/строки, отсутствие истории либо превышение
предела дают отказ целого отчёта. Старые7 native сценариев57 сохранены.

Это только наблюдение. cleanupAuthorized=false, action=retain и
unlinkedSince=null сохраняются: возраст metadata или отдельного наблюдения
не становится доказательством допустимости удаления.

## Файловая сверка и очередь ручного разбора

Команда [check-local-media-retention](../scripts/check-local-media-retention.mjs)
принимает единственный дополнительный флаг --files и только с NODE_ENV=test.
Нет apply/delete, произвольного пути или remote URL. Подтверждаются прежние
owned Docker ID/definition/loopback, fixed local origin и закрытый state.

--files использует существующий worker.observe: child сначала доказывает
kernel flock, затем внутри read-only snapshot58 проверяются БД и файлы;
отчёт публикуется только после COMMIT, валидного DONE и фактического close.
Это сохраняет порядок filesystem fence→SQL, без SQL write/claim/completion.
Параллельные штатные writers используют тот же fence. Самостоятельный
[файловый helper](../scripts/media-file-inventory.mjs) не выдаёт capability
и сам по себе не утверждает наличие kernel fence.

Используется прежний файловый inspect для точной metadata/attempt пары.
Читаются только известные final/temporary имена, проверяются private inode,
размер, SHA256/WebP, объяснимые hardlinks и стабильность. Неизвестные имена
только lstat: содержимое не открывается, symlink не прослеживается. В отчёт
попадает SHA256 имени вместо исходного имени; лишние файлы остаются на месте.

Если metadata не имеет исходного write attempt, присутствующий final отмечен
unverified: одно имя/UUID не доказывает происхождение для последующей очистки.
Файлы с incomplete/unsafe/unverified и неизвестные записи попадают в ручной
разбор с action=retain. Физического перемещения в quarantine, удаления,
исправления metadata, повтора загрузки и освобождения квоты этот режим не делает.

Pinned root descriptor, UID/0700 и lock/0600 проверяются; обход ограничен20001
записью, размер проверяемого содержимого двух известных leaves —64MiB,
сам файловый проход —3s с проверками между I/O. Общий worker deadline —5s.
До/после сравниваются namespace и inode/size/mode/uid/links/mtime/ctime.
Ошибка/смена дерева/закрытия descriptor означает отказ, а не успешный частичный
отчёт. Это модель доверенного локального root/UID; от root или писателя с тем же
UID, обходящего протокол, этот механизм не изолирует.

Запуск из корня проекта с проверенным Node22:

```sh
NODE_ENV=test node --experimental-strip-types scripts/check-local-media-retention.mjs --files
```

Отчёт сохраняется exclusive-create0600 в0700 private state вне Git. Stdout —
только счётчики, фиксированные diagnostics и путь; raw SQL, контакты, секреты,
содержимое и неизвестные имена в stdout не попадают.
