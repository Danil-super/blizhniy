## Изменения

- Главный экран использует один responsive picture: WebP мобильной и десктопной композиции, известные браузеру до исполнения JavaScript. Основное изображение eager/high; браузер выбирает одну композицию. Оригинальные PNG сохранены для совместимости старых ссылок.
- Статические изображения категорий используют Next Image с responsive srcset, lazy loading и hashed immutable источниками. Ранее первый ряд и последняя нечётная карточка загружались eagerly/high. Нижние карточки теперь загружаются при приближении к области просмотра; точный порог определяет браузер, параллельные запросы не блокируются искусственной последовательной очередью.
- PNG-источники нескольких category hero доставляются через WebP optimizer. Дом/дача использует один picture вместо двух priority image. Логотип также доставляется через optimizer.
- Текст остаётся в серверном HTML, видимом без ожидания загрузки картинок. Клиентские формы и авторизация не переводились в общий публичный кэш.
- Проверены public immutable заголовки hashed WebP и оптимизированного изображения. Персональный HTML/API сохраняют private/no-store. Обновление сайта меняет хеш ресурса, поэтому старый кэш не скрывает новый файл. Service worker с кэшированием личных данных не добавлялся.
- Для анонимной проверки сессии новый явный UI-заголовок допускает ответ 200 {user:null}; обычный endpoint сохраняет 401, защищённые ресурсы по-прежнему требуют действующую сессию. Сбой БД остаётся ошибкой доступности.

## Проверки и границы вывода

1693 native-теста; 349 проверок disposable PostgreSQL; types, lint, floor, production build. Существующее lint-предупреждение targetType сохранено. Нет изменений рабочей БД/оплаты. Новый профиль измерений не заменяет проверку реального каталога, холодного image-cache, длинных списков, нагрузки и пользовательских сценариев.

Production build без БД возвращает 404 для категорий по действующей fail-closed политике; это не дефект изображения. Поэтому responsive layout проверяется отдельным dev-стендом с синтетическими fallback-категориями, как в действующем CI, и повторяется после публикации на рабочем сайте. Production-кэш/HTML/headers проверяются отдельно на production build.

PageSpeed рекомендации CSP/COOP/Trusted Types и HSTS preload требуют отдельного совместимого внедрения с CAPTCHA, оплатой и внешними ссылками. Отсутствие этих дополнительных механизмов само по себе не доказывает эксплуатацию; несовместимые запреты не включались ради оценки Lighthouse. Production-зависимости после обновления Nodemailer: 0 известных advisory. Полный audit продолжает отмечать один moderate у development selector-parser по версии 6.1.4; действующий backport и его неизменённые regression/provenance проверки сохранены (docs/dependency-security.md).

Финальная локальная browser-проверка: 129 проверок макетов категории/инструментов прошли на dev-стенде. Главная без JavaScript проверена на ширинах 320/412/768/1440: текст виден, переполнения нет. Изображения desktop/mobile после декодирования просмотрены вручную. Production headers и фактическая WebP/immutable доставка проверены на production build.
