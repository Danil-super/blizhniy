# Короткий текст cookie-баннера: проверка точной замены

База: `8731a2d0d709ed5af79a5dca98aa91098330c183`.

26.11.2026 владелец согласовал текст «Используем cookie для работы сайта и, с вашего согласия, для анализа посещаемости.» и кнопку «Принять все». Изменение quality-floor ниже подготовлено для отдельного ручного просмотра по CONSTRAINTS.md; до подтверждения PR остается черновиком и не сливается в main.

## Что меняется в приложении

В `src/components/CookieNotice.tsx` заменяются только текст режима с аналитикой и подпись кнопки разрешения. Заголовок «Файлы cookie», ссылка `/legal/privacy#cookies`, отказ, отзыв и пункт «Настройки cookie» сохраняются. Обработчик разрешения по-прежнему вызывает `choose('granted')`. Контроллер Метрики, хранение согласия, CSP, ID и серверная конфигурация не меняются.

## Почему сработала проверка

`quality-floor` считает измененные строки с `assert` удалением проверки. В `tests/cookie-notice-ui.test.mjs` изменились две строки ожидаемого текста: название кнопки в проверке отсутствия аналитики и текст/кнопка в проверке панели с аналитикой. Все 26 вызовов `assert` сохранены. Проверки отказа, disabled до hydration, отсутствия SSR-трекинга, настроек в подвале и политики остались прежними.

Существующие браузерные проверки продолжают выполнять те же действия и assertions, используя новое точное название кнопки «Принять все».

## Конкретное изменение quality-floor для review

В существующий список `reviewedListingArtifacts` добавляется ровно одна пара полных SHA256 для `tests/cookie-notice-ui.test.mjs`:

- До: `0b215d70b469218c359b9289818716cc2904f729e1c99f0acf136aaa87c90983`.
- После: `45704c9b6c9123ca99ce4bccd7e2795952a832461e904b6c2786632ed3309ec0`.

Алгоритм guard не изменяется. Пара действует только при совпадении исходного файла в merge base и всех байтов нового файла. Другой исходный файл, любая дополнительная правка нового файла или удаление assertion в другом файле по-прежнему блокируются.

Существующий `tests/quality-floor-listing-artifacts.test.mjs` автоматически проверяет новую пару: точная замена допускается, произвольное изменение, пустой файл, упрощенный assertion, постороннее удаление и неизвестная база отвергаются. Пропуски тестов, подавления и общие исключения не добавляются.

## Проверка перед выпуском

Сохранить обязательные floor, types, lint, native, PG18, build, browser и security gates. После одобрения конкретного изменения guard и выпуска проверить короткий текст и обе кнопки на работающем сайте; уже установленный runtime ID должен сохраниться штатным переносом env-файлов.
