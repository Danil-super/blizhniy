# Проверка публичной части перед выпуском — 13.11.2026

По последнему указанию владельца сетевой тест оплаты не должен останавливать
остальную работу к первым пользователям. Этот блок проверяет публичные страницы,
исправляет подтверждённые ошибки читаемости и фиксирует измеренную скорость.
Он не закрывает весь аудит и не включает новые production-режимы.

## ЮKassa: проверка повторена, банковский тест отложен

Shop ID, сообщённый владельцем, совпал с закрытой конфигурацией. Прямой
authenticated GET `/v3/me` через Python ответил200: магазин enabled, test=true.
Затем запрос из Node с действующим transport завершился отказом до создания
fixture; отдельный10-секундный Node GET тоже истёк по тайм-ауту. На этом
банковский прогон отложен согласно условию владельца, повторов POST не было.
Контроль локальной БД:0 новых owners/orders/anchors/provider links этого прогона.
Ключи и исходные ответы не включены в отчёт; production не менялся.

Подготовленный закрытый операторский сценарий использует существующий probe,
точный57 schema gate, неизменяемый private manifest, atomic result save и
строгий TEST `/me` admission. Инженерный разбор обнаружил несовместимость
старого blocked-owner fixture с обязательным телефоном: новая fixture проходит
проверку телефона активной и блокируется до COMMIT одной транзакции.
Защиты не отключались. Исполнение этой fixture и настоящий банковский success
не проверены из-за сети. Это не подключённая пользовательская оплата сайта.

### Устранение начальной загрузки старого SDK

Лёгкий `NotificationBell` выбирает действующий PostgreSQL-компонент;
прежний LegacyNotificationBell с неизменёнными действиями/проверками вынесен
за клиентский dynamic import. Старые useAuthState, logout и подписка очистки
загружают SDK только при фактическом legacy-сценарии. Синхронный публичный
API `supabase-browser.ts`, runtime-выбор backend и серверная авторизация
не менялись; новых зависимостей/прав/настроек нет.

Инженерный разбор нашёл скрытую зависимость: старый модуль уведомлений
при импорте удалял persisted личные сообщения. Эта очистка выделена в
общий лёгкий helper и вызывается корневой очисткой независимо от SDK,
включая PostgreSQL/unavailable, отказ загрузки chunk и отключённое storage.
Обработка исходного getSession не перезаписывает более новое Auth-событие;
после unmount не устанавливается подписка и не продолжается очистка.
Оба обнаруженных запоздалых отказа воспроизведены RED → GREEN.
