# F02: очередь одобренных возвратов размещений

10.11.2026. Добавочная0052 и `createPlacementRefundWorker` продолжают private TEST pipeline0042/0040/0051. Права runtime, web-маршруты, периодический consumer, ручная и рабочая БД не меняются. Реальный API провайдера не вызывается.

## Поведение

Одобренный администратором полный возврат создаёт одну задачу по неизменяемому approval UUID. Решение0042 остаётся источником полномочия и причины; истечение исходной браузерной сессии не отменяет уже сохранённое решение. Worker не может самостоятельно одобрить возврат.

Явный `tick()` делает ограниченный backfill, получает одну задачу с token/lease и вызывает существующий approved processor. SKIP LOCKED разделяет работу нескольких потребителей. Срок lease5минут, максимум12 операционных попыток, backoff30секунд–1час. Исходные финансовые ограничения — один refund key/body,23ч55минут и12 send attempts — не расширяются. Потеря ACK enqueue/claim прекращает tick до сети; автоматического SQL retry нет.

Backfill ограничивает именно сырые строки approval по точному `(approved_at,id)` до фильтрации магазина. Курсор продвигается и на чужой строке; иначе магазин без совпадений мог бы каждый раз сканировать всю общую историю. Новый approval ставится в очередь триггером сразу, независимо от положения backfill cursor.

Транзакционный callback после financial locks проверяет token/state/expiry в authorise, policy admission и effect. Effect повторяет проверку после INSERT/readback: ожидание блокировки карточки или уведомления не даёт применить результат с истёкшей lease. Старые вызовы без callback сохраняют прежние запросы/права. До реального POST worker дополнительно проверяет монотонный deadline, консервативно полученный из оставшегося SQL lease; задержка COMMIT ACK не превращается в новую отправку. Deadline принадлежит одному tick, параллельные вызовы его не разделяют.

Pending откладывается; canceled блокирует задачу. Истёкшая lease не может завершить чужую задачу. Подтверждённый local effect имеет приоритет перед cap: после потерянного effect ACK задача завершается без повторного HTTP. Operator recovery0051 завершает/блокирует placement job отдельным AFTER trigger, не сбрасывая attempts и повторно проверяя live admin после ожидания queue lock.

## Уведомление

AFTER INSERT финансового effect создаёт одно уведомление исходному плательщику с причиной из approval и ссылкой на соответствующий раздел кабинета. Оно входит в ту же транзакцию, что и прекращение размещения/изменение оплаты. Ошибка хранилища уведомлений откатывает локальный effect; уже проверенный provider ID остаётся доступен для GET-only повтора. Повтор effect не создаёт удалённое пользователем уведомление снова.

Исторический payer мог быть удалён: уведомление вставляется только при наличии исходного аккаунта. Это сохраняет прежний0040 контракт и не подставляет другого адресата. Для legacy effect без0042 используется общий текст. Старые effect до0052 ретроспективно не уведомляются.

Дополнительную модель владелец пропустил. Использована официальная [документация PostgreSQL о SKIP LOCKED](https://www.postgresql.org/docs/current/sql-select.html), полученная через Context7; новых библиотек нет.
