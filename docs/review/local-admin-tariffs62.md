# Локальные тарифы primary-контура: кандидат62

17.11.2026. Требуется отдельный просмотр владельца до изменения guard и установки.
Рабочий production, push, российские серверы и провайдер платежей не входят.
Ярмарка/2ГИС отложены по указанию владельца; новых сценариев для них нет.

## Проблема и результат

Primary admin получает503 от прежних двух API тарифов: они используют Supabase
Bearer либо старый local-auth. Новый локальный путь использует текущую HttpOnly
сессию, закрытый Unix-сокет и существующий отдельный оператор. Общая web-роль
не получает UPDATE. По умолчанию возможность выключена.

Администратор меняет только название, точную строковую цену, срок и активность
существующего тарифа. ID/тип действия не редактируются; создания, удаления и
сброса каталога нет. Причина и подтверждение обязательны. Статус показан текстом
и цветом. Значения0.00/NULL сохраняются как разрешённые значения каталога;
подсказки объясняют ограничения checkout. Бесплатная оплата этим не добавляется.

Смена проверяет исходную ревизию, включая A→B→A через оператор. Повтор исходного
UUID возвращает прежнюю запись, не применяя старую цену заново. После потери
ответа нет автоматической повторной записи: доступны чтение результата и
явный повтор того же UUID/payload. Same-actor перепроверка входа скрывает DOM,
прерывает запрос и сохраняет pending для восстановления. Во время pending
закрытие редактора заблокировано. Жёсткая перезагрузка/навигация/выход очищают
память компонента; после нового открытия тариф читается заново с текущей ревизией.
Команды и причины не записываются в browser storage.

Проверка действующего подтверждённого admin/сессии выполняется повторно в конце
SQL-операции; блокировки пользователя и сессии удерживаются её транзакцией.
Runtime вызывает entry отдельным autocommit pool.query. Это не обещание запретить
истечение времени или последующее снижение прав после завершённой операции.

## Точный объём согласования

[Patch](local-admin-tariffs62.patch) меняет только `scripts/user-access-role.mjs`.
До согласования он остаётся неприменённым, кандидат лежит в
`admin-tariffs62/user-access-role.mjs.candidate`. Floor/workflows и старые тесты
не ослабляются. Guard принимает два полных точных admin-профиля:
61/одна callable либо61+62/две callable; main59/app60 неизменен. Helper owner-only,
любые дополнительные функции/чтение/запись/неизвестная схема/хеш отклоняются.
Пакет содержит обе доступные версии даже при выключенных tariff-командах.

[Машиночитаемый план и SHA](local-admin-tariffs62-plan.json): установить только
`database/candidates/0062-admin-tariffs.sql` в отдельном `app_admin`, добавить
одну строку его журнала и один EXECUTE существующей роли `blizhniy_user_operator`.
Новых ролей/паролей, прямого доступа к тарифам, GRANT web/финансовым/media-ролям нет.
В main app не добавляются таблицы/FK/строки журнала. Новый audit сохраняет actor,
исходные/итоговые поля и причину; UPDATE/DELETE/TRUNCATE запрещены триггером.

После свежей закрытой резервной копии и обязательного пробного восстановления —
установка только на https://127.0.0.1:3045 и включение `BLIZHNIY_ADMIN_TARIFFS=local-v1`.
До COMMIT сверяются прежние данные, права и обе схемы. Неопределённый COMMIT
проверяется чтением, без автоматического повторного применения.
При откате интерфейса сохраняются62, журнал, audit и совместимый guard;
выключается tariff opt-in, прежний user-оператор остаётся работоспособным.
