# Локальная браузерная приёмка

Проверена сборка `94cb90b0c813790c617f90aeccbcaeb2a3dc113f`. Стенд использует отдельный контейнер PostgreSQL и отдельный каталог с синтетическими аккаунтами. Статус оплаты и фотографии подготовлены штатным симулятором стенда и локальным обработчиком изображений.

| Проверка | Результат |
|---|---|
| Общедоступные страницы | 45 проверок на 320, 768 и 1440 CSS px. Серьёзных и критических нарушений axe нет. |
| Кабинет, админка, формы и страница платежа | 69 проверок на 375 CSS px с touch, 720 CSS px для проверки узкой компоновки и 1440 CSS px. Проверены также ожидаемый редирект категорий и шесть отказов маршрутов checkout без параметров. Серьёзных и критических нарушений axe нет. |
| Сессия, вход, организация и возврат к платежу | 81 браузерная проверка. После HTTP 429 сообщение получает фокус, email остаётся заполненным, пароль очищается. Повторный запрос требует нового действия пользователя. |
| Фото | Шесть проверок подготовки файла, ориентации JPEG и имени диалога кадрирования. |
| HTTP и PostgreSQL | 139 проверок. Один NAT разделяет исходный бюджет даже при разных XFF и CF-заголовках. Ответ 429 содержит `Retry-After: 900`. Новый обработчик видит сохранённый бюджет. |

В ходе прогона исправлены контраст правовых ссылок, краткий переход с низким контрастом при активации кнопки cookie и связь подписи с полем описания организации. Воспроизводимый сбой в форме организации происходил после выбора сохранённых значений в конфликте между вкладками.

Для повторного прогона допускается задать `BLIZHNIY_LOCAL_PRIMARY_FIXTURE_DIR` при `NODE_ENV=test`. Каталог должен принадлежать текущему пользователю, иметь права 0700 и быть указан каноническим абсолютным путём. Подготовить контейнер штатным `local-primary.mjs --prepare`, запустить сборку с `--background` и заполнить данные `seed-local-primary-demo.mjs`.
