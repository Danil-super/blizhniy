# Фото: клавиатура, фокус и применение кадра

15.11.2026. Локальный этап L26, без push/deploy, миграций и изменения CSP.

Медиатека объявления, общий редактор кадра и просмотр фотографий переведены
на native `dialog.showModal()`, как редактор аватарки. Общая обработка Tab
не выпускает фокус на документ на границах окна, включая состояние, когда
во время применения временно отключены все кнопки. Escape закрывает окно,
но не прерывает применение кадра. Закрытие возвращает фокус к инициатору;
для асинхронной подготовки аватарки инициатор передаётся явно, поскольку
отключение file input до открытия окна уже сбрасывает native focus.

Редакторы используют четыре обычные кнопки сдвига изображения и прежний
range масштаба. Сдвиг ограничен существующим расчётом границ, алгоритм
кадрирования и размер результата не переписаны. В просмотре фото стрелки
работают только внутри окна; номер фотографии объявляется через live region.
Кнопка выбора аватарки получила видимую рамку при фокусе её file input.

Браузерная проверка применения выявила отдельную ошибку: `fetch(data:...)`
в двух загрузчиках фото и локальном media store блокировался действующим
`connect-src`. Вместо расширения политики используется общий локальный
декодер base64 → bytes → Blob для PNG/JPEG/WebP. HTTP/blob URL, SVG, HTML и
неверный base64 отклоняются; проверки сервера и нормализация не заменяются.
Контраст кнопки «Кадр» повышен для её светло-синего фона.

## Воспроизведение и проверки

- RED: открытие старого редактора оставляло фокус вне окна; на границах
  native dialog установленный Chromium мог переводить его на документ.
- RED: закрытие вложенного окна теряло фокус из-за удаления DOM до passive
  cleanup React. Проверены возврат к живому инициатору и отсутствие попытки
  сфокусировать уже удалённый инициатор.
- RED: применение кадра на compiled стенде завершалось `Failed to fetch`.
  Тест декодера подтверждает точные бинарные байты и MIME без вызова fetch,
  отклоняет неподдерживаемые форматы и повреждённые строки.
- Существующие assertions двух fixture-тестов сохранены: добавлена только
  загрузка настоящих новых зависимостей. Guard/workflows не менялись.

Оператор `scripts/check-local-photo-keyboard.mjs [user|admin]` допускает
только owned loopback-стенд и два заранее созданных синтетических аккаунта.
Он не сохраняет публикации/аватарку, запрещает внешние запросы и проверяет
отсутствие записи фото/форм/профиля и запуска checkout. После загрузки фото
проверяются Tab/Shift+Tab, кнопки сдвига/сброса, Escape, возврат фокуса,
занятое состояние, результат 1600×1200 и scoped axe serious/critical.
Аудит контраста выполняется после завершения CSS transitions.
Для повторов нельзя сбрасывать или ослаблять лимит входа: действует пять
входов одного аккаунта за фиксированные 15 минут; можно отдельно проверить
второй синтетический аккаунт или дождаться следующего окна.

Итог на compiled HTTPS-стенде, build `4yv9I9XT0hbnvHv5K3boY`: семь
браузерных сценариев прошли на синтетическом admin-аккаунте (он использует
тот же пользовательский кабинет): вложенные окна 320/768/1440, кадр заказа,
отмена аватарки, публичная галерея заказа 320/1440. Все десять scoped axe
проверок без serious/critical; pageerror, внешних запросов и запрещённых
записей нет. Кадр PNG 1600×1200 проверен через createImageBitmap; Escape и
Tab во время искусственно задержанной подготовки не покидают редактор.
На user-аккаунте ранее воспроизведены и исправлены ошибки редактора; весь
финальный семисценарный прогон выполнен с admin из-за штатного лимита входа.

Native2794/2794 без skips, focused18/18, floor/types/lint и build прошли.
Прежнее lint-предупреждение `targetType` сохранено. Изменения БД отсутствуют,
поэтому PostgreSQL-матрица здесь повторно не заявляется.
Gitleaks не нашёл секретов в снимке 16 изменённых/новых файлов; исключений
не добавлено. Graphify и Code Graph обновлены для текущего корня проекта.

## Границы этапа

L26 полностью не закрыт: остаются Firefox/WebKit, реальный screen reader,
устройства Android/iOS, zoom и остальные критические сценарии. Изменения
проверяют управление и преобразование фото; квоты/удаление/хранение и
реальные платежи этим этапом не проверяются и не изменяются.
