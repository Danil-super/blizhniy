# Отклик, оплата и выбор исполнителя — локальный стенд

26.10.2026. Изменения действуют только в owned local primary PostgreSQL и
локальной симуляции TEST-оплаты. Production, SSH, реальные провайдеры,
списания и production-права не изменялись. Новых миграций и прав нет.

## Поведение

- У заказа нет отдельного видимого поля района. Прежнее значение в сохранённых
  заказах не теряется при несвязанной правке.
- Телефон полностью удаляется Backspace, Delete и выделением; повторная вставка
  номера форматируется. При удалении маска больше не возвращает скобку бесконечно.
- У публичных карточек заказов убран текст «Автор заказа».
- Новое/отредактированное сообщение отклика — максимум 500 символов, клиент и
  сервер. Исторические сообщения до 3000 читаются без обрезания.
- «Оплатить и отправить» сохраняет сообщение и сразу открывает страницу оплаты.
  Подтверждённая локальная симуляция доставляет отклик один раз. Неизвестный
  ответ восстанавливается по исходному ключу, без автоматического повторного POST.
- В кабинете компактная сетка откликов, статусы, дата, имя специалиста и заголовок
  заказа. Детали ограничены по ширине; специалист, профессия, сумма, «О себе»,
  сообщение, нормализованный `tel:` и закодированный `mailto:`. Обычная кнопка
  «Проверить отклик» убрана; восстановление неизвестного результата сохранено.
- Выбор исполнителя атомарно фиксирует selected-отклик. Заказ скрывается из
  локального публичного списка, страницы и выдачи фото; история заказчика
  остаётся со статусом «Исполнитель выбран». Редактирование не открывает его снова.
- Остальные доставленные отклики становятся отклонёнными. Остальные активные
  заявители, включая ещё не оплативших, получают по одному уведомлению о выборе
  другого исполнителя. Неоплаченным не присваиваются paid/delivered статусы.
- Явный отказ уведомляет адресата; сам по себе отказ не закрывает заказ.
- Закрытый заказ не принимает новую оплату отклика, выдачу/обновление платного
  окна либо новую доставку. В кабинете и восстановленном composer нет предложения
  оплатить такой отклик. Прежний платеж остаётся в истории.
- Уже committed provider payment восстанавливает тот же ID при потере привязки.
  Обычное чтение статуса сверяет только существующую simulator-запись через
  trusted callback, затем повторяет авторизацию и читает свежий результат.
  Оно не создаёт и не захватывает платёж, не доставляет закрытый отклик и не
  изображает возврат. Captured без доставки показан явно, без вечного ожидания.

## Сериализация и проверка

Решения, создание/доставка отклика и новые simulator side effects сериализуются
по строке заказа. После получения потенциально ожидавшей блокировки доступность
проверяется отдельным SQL statement. Это соответствует Read Committed PostgreSQL:
[снимки statement](https://www.postgresql.org/docs/18/transaction-iso.html#XACT-READ-COMMITTED),
[блокировки строк](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-ROWS).
Существующая selected-запись — постоянный маркер закрытия; новых таблиц нет.
Shared production и вакансии не получают политику закрытия заказа.

- `npm test`: **2012/2012**, без пропусков.
- `npm run build`: успешно, 65 страниц.
- `npm run check:fast`: floor/types/lint без ошибок; прежнее предупреждение
  неиспользуемого `targetType` в `tests/checkout-prerequisites.test.cjs` не скрыто.
- `scripts/check-local-application-payments.mjs`: **20** сценариев на реальном
  локальном PostgreSQL с runtime-ролью и rollback всех синтетических изменений.
  Включены fanout, идемпотентность, чужой доступ, отсутствие доставки до capture,
  explicit rejection, capture без delivery, first-dispatch race и lost provider link.
- `scripts/check-local-application-workflow-ui.mjs`: **3** отдельных browser-аккаунта,
  настоящая локальная БД; save/edit/pay/deliver/select/withdraw, другая нотификация,
  закрытый public404, 500, полное удаление телефона, отсутствие района/author label,
  контакты; 320/768/1024/1440px, без horizontal overflow и serious/critical axe.
  Chrome DevTools MCP отсутствует; проверка выполнена изолированным Playwright.
- Два настоящих соединения PG: actual runtime decision остановлен перед COMMIT,
  provider guard начинает работу при ещё публично открытом committed заказе,
  наблюдается `wait_event_type=Lock`; после COMMIT выбора guard отклоняет операцию.
- Потерянный ответ create воспроизведён в браузере; выбор другого исполнителя
  до intent recovery не приводит к checkout или новой payment_order.
- Контролируемая инверсия условия показа оплаты закрытого заказа дала 3 падающих
  UI-теста; исходник восстановлен побайтно, финальные проверки прошли.
- Точечный guard diff лимита 500 согласован владельцем и применён; проверки
  точной пары/дубликата/чужого файла/скрытого удаления assertions проходят.

Инженерная проверка выявила и закрыла гонку позднего первого provider INSERT,
восстановление потерянного provider link и две UI/reconciliation-ветки после
закрытия. Дополнительную проверку другой моделью владелец пропустил.
Ранее подготовленный `docs/review/application-workflow-local.patch` остаётся
неизменным историческим срезом; его хеши не удостоверяют этот инкремент.
