# Общий выпадающий список: клавиатура и проверка значения

15.11.2026. Локальный этап L26. Используется существующий DropdownSelect:
типы/категории/подкатегории и город объявления, SelectInput каталога,
legacy-редактор специалиста и категория ярмарки. Основной ProfessionSelect
и CitySelectField имеют отдельные реализации и этим изменением не заменяются.

Сохранены внешний вид, роль кнопки открытия, controlled/uncontrolled API,
имена и значения FormData. Применена существующая пара button + listbox:
фокус перемещается на варианты, а не изображает combobox на кнопке.
Список имеет связанное имя, selected state и один вариант с tabIndex0.
Стрелки/Home/End/PageUp/PageDown перемещают фокус, Enter/Space подтверждают,
Escape отменяет просмотр и возвращает кнопку, Tab закрывает список и
сохраняет обычный порядок перехода. Набор букв поддерживает кириллицу и
циклический выбор по повторяющейся букве. Просмотр не меняет значение формы.
Вариант прокручивается в видимую область; пустой обновлённый список закрывается.

Обязательная proxy-input прежде имела readOnly и не участвовала в native
constraint validation. Теперь пустое значение даёт checkValidity=false,
показывает связанную ошибку и открывает выбор; подтверждение допустимого
варианта очищает ошибку. Proxy остаётся без name и не добавляет второй
параметр формы. Именованное hidden-поле по-прежнему содержит только значение
существующего варианта. Proxy размещена после кнопки, чтобы не перехватывать
implicit label первого labelable элемента. Серверная валидация не изменена.

Начало pointerdown больше не подтверждает выбор: подтверждение происходит
по click или клавише. Это необходимо для прокрутки списка касанием.
Контраст placeholder и выбранного варианта исправлен существующей палитрой.

## Воспроизводимость

`tests/dropdown-keyboard.test.cjs` исполняет настоящий компонент с явными
границами React/DOM. Первые четыре сценария дали RED до изменения, отдельный
пятый/шестой проверяют повтор букв, границы и опустевший список. Assertions
старых тестов и guard/workflows не менялись.

`scripts/check-local-dropdown-keyboard.mjs` допускает только owned loopback
и заранее созданного синтетического пользователя. Проверяет настоящую
compiled форму объявления на 320/768/1440: клавиатуру, FormData без отправки,
native required/ошибку, scoped axe и сенсорную прокрутку через Chromium CDP.
Внешние запросы блокируются, сохранение формы/фото и checkout не выполняются.

Итог на build `pTjoSv1LDBnn-iVyzLjZY`: три полных браузерных сценария
320/768/1440 прошли на user-аккаунте. Проверены переход к следующему полю
по Tab и к кнопке по Shift+Tab, подтверждение ровно одного нового значения,
сохранение прежнего при Escape/Tab, набор кириллицы, checkValidity=false
у пустого города и true после выбора. Все шесть scoped axe без
serious/critical; pageerror/внешних запросов/записи формы нет.

При калибровке оператора обнаружены две особенности: CSS smooth-scroll
делал координаты жеста устаревшими, а synthesizeScrollGesture с touch в
установленном headless Chromium не прокручивал даже обычный контрольный div.
Оператор позиционирует список мгновенно, проверяет elementFromPoint и
передаёт touchStart/move/end с кадрами между движениями. Проверяется именно
рост scrollTop живого списка и неизменность FormData; успех только по
отсутствию ошибки протокола не принимается.

Native2800/2800 без skips, focused6/6, floor/types/lint и build прошли;
прежнее предупреждение targetType сохранено. Guard, старые assertions и
зависимости не менялись. Матрица PostgreSQL для этого UI-изменения не
повторялась. Graphify/Code Graph обновлены для того же корня проекта.
Gitleaks не нашёл секретов в пяти изменённых/новых файлах; исключений нет.

## Границы

Это один общий компонент, а не завершение L26. Firefox/WebKit, реальные
screen readers/мобильные устройства и остальные элементы требуют отдельной
проверки. Настоящие TEST-платежи отложены: короткое подключение к API ЮKassa
15.11 снова истекло по тайм-ауту; секреты не запрашивались и не передавались.
Production, роли, БД, миграции, платёжные режимы и CSP не изменяются.
