# Карточки администратора и аватар — локальная проверка 21.10.2026

Область: существующий стенд `https://127.0.0.1:3045`, только синтетические
аккаунты/файлы. Production, реальные платежи, SMTP, миграции и права БД не меняются.

## Админка

Список использует ту же компактную иерархию, что кабинет: заполненный кадр 4:3,
тип, статус, название, цена, город/район и причина блокировки. Действия остаются
административными: подробности и прежняя блокировка с причиной; полномочия
владельца или оплаты не подмешиваются.

`list` получает добавочное поле `card` одним SQL-запросом. Строгий старый контракт
`inspect`/`block` сохранён. Клиент принимает старый summary без `card` для совместимости,
но проверяет все поля нового summary. Все изображения проходят существующий
admin/ownership reader; публичные URL для приватных файлов не создаются.
Общая очередь ограничена тремя параллельными загрузками, без автоматических повторов.

В галерее видны миниатюры и счётчик. Одновременно монтируются максимум восемь
миниатюр; стрелки открывают остальные. Основной кадр привязан ключом к ID фото,
чтобы при переключении прежнее изображение не выдавалось за новое.
Проверка девяти разных кадров сравнивает не только счётчик, но и пиксели изображения.
Однотонные голубые изображения прежних технических объявлений — реальные
синтетические исходники, а не отсутствие загрузки.

## Аватар

Воспроизведён исходный сбой при 640×400: fixed-окно обрезало кнопку «Применить»,
нижняя навигация могла перекрывать редактор. Используется подписанный native
dialog в top layer, с ограниченной высотой, прокруткой и клавиатурной навигацией.
Во время записи закрытие отключено. Для обычных ошибок показан текст внутри
редактора; успешная запись даёт явное сообщение.

Дополнительно воспроизведена потеря кадра при размонтировании профиля во время
перепроверки сессии. Выбранный кадр хранится отдельно от сохранённого профиля
в owner-scoped React-памяти provider, как несохранённые настройки. При неизвестной
идентичности он не выдаётся; выход или другой аккаунт очищают выбор. Browser
storage и новые серверные хранилища не используются.

Неопределённая запись по-прежнему закрывает возможность повторения: сначала
«Обновить профиль», новое чтение/revision, затем восстановленный кадр и явное
«Применить». Наличие кадра в памяти не означает, что аватар сохранён, и не
заменяет cookie-проверку, CAS или guard неизвестного результата.
