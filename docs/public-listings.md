# Публичные обычные объявления — российский контур

19.10.2026. Локально подключены read-only repository и публичные потребители для четырёх видов объявлений. Первичная форма брони также подключена отдельным локальным срезом, см. [bookings.md](bookings.md). Это ещё не завершение L10/L15 или полного переноса: публикация/оплата, счётчик/сводка продавца и доставка остаются открытыми. Нового кода на VPS пока нет.

`PostgresPublicListingStore` читает только опубликованную, оплаченную, неистёкшую и одобренную текущую revision. Автор подтверждён и не заблокирован; город, корневая/дочерняя категория действуют; все фото принадлежат автору и готовы. SQL eligibility общий с admission бронирования, без изменения его поведения. SQL-сбой не выдаётся за пустую успешную выборку и не запускает старый backend.

Публичный DTO строится allowlist-ом: только имя продавца из частного профиля, явные контакты самого объявления, реальные категории, цена, локальные фото. Скрытые адрес/координаты, account email/phone, реквизиты организации и credentials не сериализуются. Нулевые публичные координаты сохраняются. В списке только обложка; детальная карточка получает упорядоченную галерею. Это ограничивает многократное копирование больших photo-массивов. Запросы имеют limit/offset и устойчивую сортировку с UUID tie-breaker.

В postgres-режиме прежние публичные detail/list/category/seller интерфейсы выбирают новый repository до чтения legacy-конфигурации. Не scoped private detail не является владельческой авторизацией и ничего не возвращает. Category-ID, предложенный вызывающим кодом, не считается доказательством принадлежности: фильтр основан на настоящем FK/slug. Сохранены pageSize+1, offset и все страницы существующего seller-интерфейса (по200 строк на SQL-запрос). Последний всё ещё агрегирует все записи продавца в памяти; полноценная пагинация seller и серверный поиск остаются отдельным performance-пунктом до массового запуска.

Фото `/api/listings/:listingId/photos/:fileId` используют ту же ограниченную политику, что work/service: текущая SQL-доступность до чтения частного файла и повторная проверка после него, WebP до2МБ, общий admission4, no-store/nosniff. Нет прямой отдачи закрытого каталога и распознавания авторизации только по UUID.

## Точные права

Согласован и после проверок применён оператор `scripts/grant-public-listing-read.mjs`: только `SELECT(created_at,view_count)` существующей роли `blizhniy_runtime` на `app.listings`. Проверяет точную цель, PostgreSQL18, неизменённые18 migration hashes, атрибуты роли и ACL до/после. Не вызывается запуском приложения или деплоем. Не добавляет INSERT/UPDATE, широких table privileges или делегирования. Повтор безопасен, неизвестный COMMIT не повторяется автоматически.

Свежий production runtime-login подтвердил чтение двух полей через SELECT LIMIT0. Все пять UPDATE WHERE false для них и ранее согласованных `is_paid,published_at,expires_at` получили42501. Данных, таблиц, user roles, SSH и оплаты не меняли. Это изменение ACL, не установка нового кода.
