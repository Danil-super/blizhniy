# Счётчик просмотров объявлений в PostgreSQL

В кабинете и каталоге источником числа просмотров служит поле `app.listings.view_count`. При выключенной записи сайт показывает сохранённое значение. Ошибка сети или хранилища не увеличивает его в браузере.

## Подготовка рабочего контура

Кандидат 0066 и файл `database/permissions/listing-views.sql` проверяются на одноразовой базе. **Установка в рабочую БД пока заблокирована.** Внешний ключ из журнала просмотров в таблицу объявлений меняет проверяемую структуру БД. Действующий обработчик TEST-платежей при такой структуре отклоняет запуск, даже когда запись просмотров выключена. Выложить код приложения можно с прежней БД.

Для установки нужен проверенный на копии БД выпуск финансовых обработчиков, принимающий точное изменение структуры и журнала миграций. Затем нужны проверка восстановления, сверка прав и решение владельца о включении. Веб-роли нужны `USAGE` в схеме статистики и `EXECUTE` одной функции. У финансовых ролей прав на запись просмотров нет. Приложение включает запись только при `BLIZHNIY_LISTING_VIEWS=enabled` в режиме PostgreSQL.

## Как считается просмотр

При первом открытии браузер гостя возвращает серверу защищённый HttpOnly-cookie со сроком один год. Вошедшего пользователя сервер определяет по действующей сессии. Повторное открытие тем же гостем или тем же аккаунтом сохраняет прежнее число. Другой браузер без входа, очистка cookie, переход от гостя к аккаунту и смена серверного ключа могут дать новый просмотр. Это количество просмотров по таким идентификаторам, а не оценка числа людей.

В журнале хранятся ID объявления и отдельный для этого объявления HMAC. Удаление объявления удаляет его журнал. После снятия объявления новые просмотры не записываются. Исходное накопленное число сохраняется.
