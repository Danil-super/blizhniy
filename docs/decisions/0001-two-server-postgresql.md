# ADR-001: Два российских сервера и PostgreSQL без Supabase

Статус: принято владельцем 09.10.2026. Реализация не завершена.

## Контекст

Владелец исключил Supabase, включая self-hosted вариант, и одобрил два существующих российских сервиса. VPS приложения имеет 2 vCPU / около 2 ГБ RAM / 40 ГБ диска; отдельная управляемая БД — PostgreSQL 18.6 Timeweb. Действующий код использует Supabase Auth, PostgREST и Storage, поэтому смена URL не является миграцией.

## Решение

- Next.js, серверная авторизация, API и платёжные обработчики выполняются на VPS сайта.
- Аккаунты, хеши паролей/токенов, сессии и предметные данные сохраняются в PostgreSQL. Браузер не имеет прямого доступа к ней.
- Доступ к PostgreSQL — node-postgres (`pg`), параметризованные SQL, ограниченный пул и транзакции на одном соединении. Удалённый TLS проверяет CA и имя, даже при подключении к указанному IP. Не используем PostgREST-совместимый SQL-парсер и не воспроизводим роли/таблицы Supabase как заглушки.
- Фотографии находятся вне release-каталогов на VPS; метаданные/владение — в БД, стартовая квота 5 ГБ. Независимая копия файлов в РФ обязательна до открытия пользователям; третий VPS не нужен.
- Инициализация чистая: только проверенные справочники и тарифы. Исторические SQL и тесты сохраняются как доказательства, но не исполняются вслепую.

## Альтернативы

Self-hosted Supabase исключён владельцем. Фото в PostgreSQL увеличивают нагрузку на БД и резервирование; не выбираем на старте. Дополнительные VPS, Redis и отдельный тяжёлый сервер Auth не требуются для начальной нагрузки. Российское объектное хранилище можно подключить для независимого backup/роста файлов после согласования, не выдавая его за уже оплаченную услугу.

## Последствия

Нужно заменить Auth, HTTP REST и Storage-контракты, проверить ownership/контакты/платежи и подготовить независимое восстановление. Production переключается только после готовности замены. Одного размещения в РФ недостаточно для юридического заключения; внешние потоки и документы проверяются отдельно.
