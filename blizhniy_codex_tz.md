# ТЗ / промт для Codex: платформа объявлений «БЛИЖНИЙ»

## 1. Цель проекта

Нужно разработать MVP веб-платформы «БЛИЖНИЙ» — региональной доски объявлений и раздела работы/специалистов для Краснодарского края.

Платформа должна объединять:

1. Доску объявлений / ресейл:
   - продам;
   - куплю;
   - меняю;
   - отдам даром.

2. Раздел «Работа»:
   - вакансии от организаций/заказчиков;
   - анкеты специалистов/исполнителей;
   - классификатор специалистов по алфавиту и поиску.

Стартовая география: Краснодарский край. Архитектуру нужно заложить так, чтобы позже можно было добавлять новые города, области и регионы без полной переделки проекта.

---

## 2. Предпочтительный стек

Предлагаемый стек:

- Next.js
- TypeScript
- Tailwind CSS
- shadcn/ui
- Supabase или PostgreSQL
- Supabase Auth / Auth.js

Если в проекте уже выбран другой стек, адаптировать решение под текущий стек, но сохранить бизнес-логику.

## 4. Основные роли пользователей

В проекте должен быть один базовый аккаунт пользователя. Один пользователь может выполнять разные действия.

Роли/режимы:

1. Гость:
   - смотрит объявления;
   - смотрит специалистов;
   - смотрит вакансии;
   - использует поиск и фильтры;
   - не платит.

2. Зарегистрированный пользователь:
   - может размещать объявления;
   - может создать анкету специалиста;
   - может разместить вакансию;
   - может откликаться на вакансии;
   - управляет своими публикациями в личном кабинете.

3. Продавец:
   - размещает объявления;
   - платит за публикацию объявления.

4. Специалист / исполнитель:
   - создает анкету специалиста;
   - указывает навыки, описание, фото, стоимость работ;
   - выбирает категорию/профессию из классификатора;
   - может платно откликаться на вакансии.

5. Организация / заказчик:
   - размещает вакансию;
   - указывает название организации, описание вакансии, стоимость/зарплату, фото при необходимости;
   - платит за размещение вакансии.

6. Администратор:
   - управляет пользователями;
   - управляет объявлениями;
   - управляет вакансиями;
   - управляет анкетами специалистов;
   - управляет категориями;
   - управляет классификатором специалистов;
   - видит оплаты;
   - может редактировать/удалять публикации.

## 5. Главные сущности проекта

Типы объявлений:

- продам;
- куплю;
- меняю;
- отдам даром.

Поля объявления:

- id;
- автор;
- тип объявления;
- категория;
- подкатегория;
- регион;
- город;

- дата создания;
- дата публикации;
- срок размещения;

В MVP: после оплаты объявление сразу публикуется. Модерацию технически предусмотреть, но пока можно оставить отключенной.

## 8. Страница «Работа»

Нужно реализовать страницу «Работа» по логике макета.

Основная идея:

Одна страница, на которой визуально две стороны:

1. Левая сторона:
   - «Я ищу работу»;
   - вакансии / заказчики / организации;
   - кнопка «Разместить вакансию»;
   - карточки новых вакансий;
   - кнопка «Все вакансии».

2. Правая сторона:
   - «Я ищу специалиста»;
   - специалисты / исполнители;
   - кнопка «Создать анкету специалиста»;
   - классификатор специалистов с поиском;
   - карточки новых специалистов;
   - кнопка «Все специалисты».

Важно: не делать два бесконечных списка на одной странице. На общей странице показывать короткие подборки. Для полного просмотра сделать отдельные страницы:

- `/rabota/vakansii`
- `/rabota/specialisty`

На мобильной версии блоки должны идти друг под другом.

## 9. Кнопки связи

В карточках объявлений, вакансий и специалистов должны быть кнопки:

- Позвонить;
- Написать сообщение;
- Видеозвонок.

Для MVP:

- «Позвонить» — ссылка `tel:`;
- «Написать сообщение» — можно сделать ссылку на WhatsApp/Telegram или простую форму;
- «Видеозвонок» — пока реализовать как кнопку/ссылку на внешний сервис, не делать собственный видеочат внутри сайта.

Если данных для Telegram/WhatsApp/видеосвязи нет, кнопку можно скрывать или делать неактивной.

## 11. Логика оплаты

Сейчас нужно заложить архитектуру под оплату.

У заказчика есть расчетный счет, онлайн-кассу нужно будет подключить.

В MVP логика:

1. Пользователь создает объявление/вакансию/отклик.
2. Сайт создает заказ на оплату.
3. Пользователь переходит к оплате.
4. После успешной оплаты платежная система отправляет webhook.
5. Сайт меняет статус:
   - объявление → published;
   - вакансия → published;
   - отклик → sent/paid.
6. Пользователь получает email-уведомление.

Пока модерация отключена. После оплаты публикация происходит сразу.

Нужно сделать код так, чтобы позже можно было подключить реальную платежную систему. На первом этапе допускается сделать mock/fake payment provider для разработки:

- кнопка «Оплатить»;
- тестовый успешный платеж;
- обновление статуса;
- запись payment record;
- email-уведомление.

## 21. Важные ограничения

Не делать в первой версии:

- внутренний чат;
- собственный видеозвонок внутри сайта;
- доставку;
- безопасную сделку;
- рейтинги;
- отзывы;
- мобильное приложение;
- сложную модерацию;
- парсинг чужих сайтов;
- полноценную онлайн-кассу до получения финальных данных от заказчика.

Заложить архитектуру так, чтобы эти функции можно было добавить позже.

## 22. Главные пользовательские сценарии

### Сценарий 1. Размещение объявления

1. Пользователь регистрируется.
2. Выбирает «Разместить объявление».
3. Выбирает тип: продам/куплю/меняю/отдам даром.
4. Выбирает категорию и город.
5. Заполняет название, описание, цену, фото, контакты.
6. Сайт создает заказ.
7. Пользователь оплачивает.
8. После оплаты объявление публикуется.
9. На email приходит уведомление.

### Сценарий 2. Размещение вакансии

1. Организация регистрируется.
2. Выбирает «Разместить вакансию».
3. Заполняет название организации, вакансию, описание, зарплату, город, фото.
4. Выбирает категорию специалиста.
5. Оплачивает публикацию.
6. Вакансия публикуется.
7. На email приходит уведомление.

### Сценарий 3. Создание анкеты специалиста

1. Специалист регистрируется.
2. Выбирает «Создать анкету специалиста».
3. Заполняет фото, описание, навыки, стоимость работ, город.
4. Выбирает профессию из классификатора.
5. Анкета появляется в каталоге специалистов.

### Сценарий 4. Отклик специалиста на вакансию

1. Специалист открывает вакансию.
2. Нажимает «Откликнуться».
3. Сайт создает заказ на оплату отклика.
4. Специалист оплачивает.
5. После оплаты отклик отправляется организации.
6. Организация получает контакты специалиста.
7. На email приходит уведомление.
