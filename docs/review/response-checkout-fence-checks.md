# F03: замена ожиданий, допускавших потерю оплаченного отклика

База: `7093c64`. Предложение только для `scripts/check-local-application-payments.mjs`; guard/workflows и остальные тесты не меняются.

Точный diff: [response-checkout-fence-checks.patch](response-checkout-fence-checks.patch).

Старый сценарий позволял изменить revision/удалить заказ или выбрать исполнителя, пока оплата другого отклика не завершена. Он ожидал, что уже списанный отклик останется недоставленным. Новая защита 0046 запрещает именно это состояние: изменение/выбор возвращает PWR01, после достоверного отказа оплаты либо доставки действие разрешено.

Предлагаемые замены:

- Изменение revision и удаление во время оплаты отклика отклоняются; исходная оплата доставляет отклик один раз, включая повтор, с одним уведомлением.
- Выбор исполнителя ожидает завершения остальных активных оплат. Достоверная отмена в локальном провайдере завершает их; неоплаченные авторы получают уведомление о выборе другого.
- При уже списанной, но ещё не доставленной оплате выбор отклоняется; чтение восстанавливает исходный capture, доставка/повтор дают один receipt и одно уведомление, затем выбор разрешён.
- Потеря ответа провайдера сохраняет прежний ID. Выбор блокируется до восстановления исходной оплаты и её достоверной отмены. Повтор после отмены не возобновляет списание.
- Синтетические аккаунты получают собственные случайные подтверждённые номера, чтобы проверка работала с включённой политикой телефона, не отключая её.

Все проверки CSRF/ownership, immutable receipt/body/provider ID, возврата размещения, справочников, отказа БД, истечения срока, ограничения прав и разовой доставки сохранены. Новый код миграции устанавливается внутри общей rollback-транзакции, только если отсутствует; ни данные, ни DDL, ни grants проверки не сохраняются.

Доказательство подготовки: кандидат с этим diff выполнен из временного файла с теми же исходниками и разрешением относительных импортов относительно исходного runner. Все 20 сквозных проверок на настоящем owned local PostgreSQL прошли; транзакция откатилась. HTTP провайдера — локальный симулятор; реальных запросов и списаний нет. После согласования требуется повтор исходной командой.

Изменение смысла защищённых проверок требует review владельца по CONSTRAINTS.md, раздел «Действующие механизмы». Владелец одобрил точный diff 10.11.2026; он применён, исходный runner прошёл все 20 проверок. Guard не менялся. Production не затрагивается.
