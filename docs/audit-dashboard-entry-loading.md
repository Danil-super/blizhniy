# Разделение загрузки входа и кабинета — 13.11.2026

Локальный инкремент после2272d1e. Предыдущий серверный dynamic-import
эксперимент не уменьшил загрузку `/auth`; здесь разделены фактические
client-entry зависимости. Production и два российских сервера не менялись.

## Что изменилось

- AuthPage вынесен в `auth/AuthPage.tsx`; существующий AuthForm загружается
  через небольшой клиентский LazyAuthForm с включённым SSR. Рабочая форма
  PostgreSQL и выбор backend на `/auth` прежние. Старый экспорт AuthPage
  из MvpDashboard сохранён.
- Серверные страницы кабинета вынесены в `cabinet/CabinetPages.tsx`;
  десять маршрутов импортируют их напрямую. Они больше не получают
  административные client-компоненты через общий MvpDashboard.
- Shell, NavPills, ActionLink и единственный объект cabinetNav находятся в
  DashboardShell. Старые и новые экраны используют один объект навигации;
  кабинетный профиль по-прежнему появляется только для неё.
- Два прежних helper строк вынесены в dashboard-rows с тем же fallback gate.
  paymentRows также используется прежним adminPaymentRows. Типы из
  CabinetClient импортируются только как type и не добавляют runtime-ребро.

Тела всех16 перенесённых функций побайтно совпали с исходной2272d1e при
сравнении AST. Единственное изменение старого UI-теста — путь поиска
перенесённого AuthPage; assertions, форма и проверка единственного H1 прежние.
Добавлены проверки зависимостей маршрутов, active navigation, области профиля,
nullable create action и запрета demo rows вне разрешённого fallback.
Guard, workflows, API, схема/права БД и зависимости не менялись.
