# Покрытие непосредственно исполняемого кода

## Запуск и границы

```bash
npm run --silent test:coverage:native
```

Нужен Node22. Команда дополнительная: она не заменяет `npm test`, SQL integration, сборку или браузерные проверки. Зависимости и lockfile не изменены. Runner фиксирует девять существующих direct-import test files; TypeScript исполняет Node через strip-types. Преобразованные `vm` fixtures не включены: их имена могут совпадать с исходниками, но позиции исполняемого JavaScript не являются достоверным покрытием TypeScript.

Выбраны `postgres`, `identity`, `auth-http`, `postgres-tariffs`, `server-request-timeout`, `media-image`, `media-file-protocol`, `media-worker-protocol`, `local-reference-admin`. Это начальный backend subset, не весь backend. Расширять список можно после проверки прямого исполнения источников и их зависимостей; автоматическое включение всего native suite пока дало бы ложную атрибуцию VM-кода.

В stderr выводятся результаты тестов и таблица Node; в stdout — один JSON. Для сохранения JSON запускайте сам runner, чтобы npm banner не попал в файл:

```bash
node scripts/run-native-coverage.mjs > /tmp/blizhniy-native-coverage.json
```

Репортёр читает документированные события [`test:coverage` и `test:summary`](https://nodejs.org/download/release/v22.23.0/docs/api/test.html#event-testcoverage), а не текст TAP/spec. Он принимает только источники `src/`, отдельно перечисляет **неизмеренные** файлы, считает взвешенные totals и показывает номера непокрытых строк. Отсутствие данных, дубликаты, некорректные счётчики, проваленные/пустые/пропущенные тесты означают отказ, не успешный baseline. Exit code обязателен: наличие JSON само по себе не заменяет проверку завершения процесса.

`unmeasuredFiles` — инвентаризация runtime-кандидатов `.ts/.tsx/.js/.jsx/.mts/.cts` из `src/` (без `.d.ts`), не расчёт их покрытия. `null` для процента при нулевом знаменателе означает отсутствие измеряемых элементов, не 100%. Счётчики строк/ветвей/функций — метрики Node/V8, не доказательство покрытия каждого условия бизнес-логики. `changedLineGate=false`: порог изменённых исполняемых строк ≥80% пока не включён.

Все пути в таблице относятся к `src/lib/`. Непокрытые участки identity включают операции создания/отзыва сессии и разрешение пользователя; по этому subset нельзя подтверждать полный сценарий авторизации. Платёжный lifecycle, ownership публикаций, HTTP wiring, UI и SQL-функции этим runner не проверяются.

Runner/reporter проверены шестью отдельными тестами, включая реальный дочерний Node runner с TypeScript import. Дочерняя проверка удаляет только унаследованный `NODE_TEST_CONTEXT`: иначе Node воспринимал её как test worker и не выдавал независимый отчёт. Инверсия проверки успешного завершения поймана тестом и восстановлена. После восстановления общий regression suite прошёл 1026/1026 без пропусков, types/lint — без ошибок (одно прежнее lint warning), quality floor и diff check — чистые. App source и dependencies не менялись; новой сборки приложения в этом инкременте нет.

Нельзя включать общий 80% gate только по загруженным модулям: отсутствие изменённого файла в отчёте не должно считаться успехом. Performance/accessibility baseline выполняется на изолированном стенде отдельно.
