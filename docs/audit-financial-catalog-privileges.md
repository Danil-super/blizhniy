# F02: единая проверка системных прав финансовых ролей

Подготовлено10.11.2026, итоговая регрессия11.11.2026. Локальное усиление guard; установленный обработчик и production не обновляются.

Прежний `payment-reconciliation-role.mjs` пропускал дополнительные права на системные функции/таблицы, CREATE в системных схемах и параметры кроме session_replication_role. Десять реальных регрессий воспроизвели приём таких прав и исходниками, и автономным пакетом. Файлы сервера и пароли не читались: тесты меняют/восстанавливают только ACL временной синтетической PostgreSQL и проверяют допуск.

`financial-catalog-privileges.mjs` переиспользует проверенные проверки роли возвратов: все namespace CREATE/grant options, ограниченный USAGE, повышенные права параметров и дополнительные системные ACL относительно initdb. Теперь оба guard вызывают этот модуль в своей READ ONLY транзакции после проверки личности и журнала. Точный список штатных metadata SELECT PostgreSQL18.6 сохранён; внутренние представления и новые права этим списком не разрешаются. Родительские guard по-прежнему возвращают только прежнюю общую ошибку без SQL/реквизитов.

Нестандартные объекты проверяются по точным namespace исключениям pg_catalog/information_schema; произвольный pg_ префикс больше не исключает схему. В перечень relations добавлен relkind t: SELECT на реальную TOAST-таблицу должен остановить допуск даже без USAGE на pg_toast. Отдельная регрессия это проверяет для старого guard и его пакета; проверка роли возвратов также дополнена таким GRANT.

Сборщик `build-payment-worker.mjs` включает новый модуль. Реальные тесты строят автономный пакет, загружают из него guard и проверяют те же положительные/отрицательные состояния БД. Зависимости, runtime factory, финансовые колонки/GRANT, роли, миграции, допустимые журналы24/25/32/33 и lock guards не изменяются. В прежнем preflight добавлены statement_timeout5s и lock_timeout1s, как у роли возвратов. Fake fixture схем32/33 отвечает на дополнительные read-only metadata запросы; существующие assertions сохранены.

Целевой набор367/367 и проверка роли возвратов46/46 прошли. Итоговый повтор11.11.2026: native2576/2576 и все13 обязательных PG-наборов785/785 за233.5s без skips. Журналы сохранены в локальном закрытом каталоге audit-checks вне Git. Независимое ревью потребовало причинного теста pg_toast; после добавления новых замечаний не найдено. Дополнительную модель владелец пропустил. Точный diff в [review](review/financial-catalog-transfer.md) одобрен владельцем только для локального сохранения после проверок.

Код прежнего managed membership predicate не меняется; это не продление production-допуска PAYMENT-PG18-ADMIN-20261020, дата пересмотра которого03.11.2026. До production-обновления нужен отдельный пересмотр. У новой refund-роли все memberships запрещены. Фактические дополнительные права на production не исследовались; наличие там таких GRANT не утверждается.

Открыты полная аттестация business-объектов БД, интерфейс/роль оператора, service/artifact/TLS/магазин preflight и настоящая TEST/fiscal приёмка. Эта проверка не заменяет изоляцию доверенного финансового процесса и не включает возвраты или LIVE.
