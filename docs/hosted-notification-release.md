# Обновление схемы уведомлений с 0084 до 0087

Пакет предназначен для схемы размещений и возвратов TEST. Исходный журнал из 75 записей задаёт `getHostedRefundReleasePlan(84)`. Целевой журнал из 78 записей задаёт `getHostedRefundReleasePlan(87)`. Модуль сверяет SHA256 каждого файла. `getHostedNotificationUpgradeSql()` формирует транзакцию с блокировкой журнала, сверкой исходной версии и записью всех трёх миграций. [План SQL](../scripts/publication-test-release-plan.mjs)

| Миграция | SHA256 |
|---|---|
| `0085-business-email.sql` | `33a12166b8459591dc9689ffd7ffcd255472106a45f7711c420d838543440d68` |
| `0086-push-subscriptions.sql` | `e411a73fd26c376c613eb8034b780b343a4be295b8809a8d8e6b9a8407472a01` |
| `0087-push-delivery.sql` | `791bdcb617df67dd370608b662400d796b68f47295bce7971b1ec543c74867d7` |

1. На закрытом контуре снять согласованную копию и проверить восстановление. Собрать пакет сверки с `buildPaymentWorker(destination,{publicationTest:true})` и два пакета возвратов с `schema:87`. Зафиксировать SHA сборки, контрольные суммы пакетов и установленные роли. Проверить пакеты с журналом 0084 под штатными ролями.
2. Выполнить сверенный SQL в согласованное окно, сохраняя `BLIZHNIY_PAYMENT_MODE=test`. После 0087 повторить запуск финансовых служб с `--check` там, где он предусмотрен, и подтвердить новое TEST-исполнение. При сверке принимаются точные каталоги исходной установки и логического восстановления. Для нового пакета в схеме `app` изменились три внешних ключа и восемь триггеров. В двух новых схемах проверяются каталог и права, включая доступ к отдельным столбцам и default ACL.
3. Выдать почтовому воркеру и Push-воркеру отдельные логины. Пакеты прав дают каждому USAGE своей схемы и EXECUTE трёх функций. HTTP-роль получает USAGE `app_push` и три функции работы с подпиской. Финансовые роли сохраняют прежние права. Перед первым запуском таймеров проверить конфигурацию TLS и выполнить `--check` соответствующего воркера. [Права почты](../database/permissions/business-email.sql) · [Права HTTP](../database/permissions/push-subscriptions.sql) · [Права Push-воркера](../database/permissions/push-delivery-worker.sql)
4. При сбое остановить таймеры доставки и сверить журналы новых каналов. Обратные SQL проверяют пустоту журнала или таблицы подписок перед удалением объектов. Для отката пустой схемы порядок обратный, 0087 → 0086 → 0085, с согласованной сверкой журнала миграций. При накопленных записях сохранить схему и восстановить работу совместимой сборкой. [Откат 0087](../database/candidates/0087-push-delivery.down.sql) · [Откат 0086](../database/candidates/0086-push-subscriptions.down.sql) · [Откат 0085](../database/candidates/0085-business-email.down.sql)

Рабочий допуск требует сверки фактического журнала, штатного `--check` установленных пакетов и успешной доставки через тестовые приёмники.
